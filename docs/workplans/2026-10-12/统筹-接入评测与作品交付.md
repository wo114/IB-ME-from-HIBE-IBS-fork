## 2. 组合登记与实验记录模板

每个 case 填下列信息，未测值留 `null` 并说明状态，不能填 0。算法数、参数数、格式数、组合数分别统计。

| 字段组 | 必填内容 |
|---|---|
| 版本 | case ID、源码提交、运行版本、输入/结果文件 SHA-256、日期、操作者 |
| 两原语 | HIBE/IBS 稳定 ID、论文/算法版本、各自完整参数快照与 profile |
| 构造 | 王老师构造位置、Baseline/BYTEAUTH、direct/Hybrid、wire/签名格式 |
| 层级状态 | source/spec/component/backend/combination；G-run/G-formal；教学、负控、正式参数标记 |
| 模型 | 两个原语的困难假设、匿名/认证/固定服务条件、ROM/QROM/标准模型范围、仍未成立前提 |
| 输入 | 身份原始字节/编码长度、消息长度、内层 seed/身份、载荷预算、用户/消息数量 |
| 执行 | CPU/内存/OS/软件依赖、RNG 类型、冷/热/缓存/恢复、重复数、超时/资源限额 |
| 验收 | 四种匹配、伪造/自我伪造/接收者重签、wire 修改/解析、跨公钥/profile、恢复/中止/并发；第一拒绝层 |
| 比较 | 原语与完整 Encrypt/Decrypt 的中位数/IQR、mpk/ek/dk/ct 实际规范字节、峰值进程资源 |
| 失败 | 原始次数/概率估计口径、异常/超时、跳过/阻塞、已知攻击、不能承诺的性质 |

公开支持一个配对前须完成该配对真实验收；相同接口不自动证明每个配对。依赖参数/包装改变后仅重跑受影响的 case。大采样观察产物再继续，不靠重启淘汰失败。

## 3. 联合优化与三代表的统一口径

“A+B<C”的 A、B 和 C 必须先定义相同工作、输入、安全目标和计时边界：比较未合并公共操作的完整实现与共享后的完整实现。记录预处理/发钥如何摊销、整个加密/解密或服务批次成本，不能把裸 HIBE 调用与裸签名相加去比较包含不同工作的 C。

候选优化先考虑规范编码、公开预计算、相同散列前缀和合法固定状态复用。分别开关这些因素做消融，保留 CPU/内存/通信与失败成本。秘密随机性/噪声/陷门/消息语义改变须先核条件，不自动共享。实际收益不成立也报告原因，不倒推参数来填创新结论。

三代表按低通信/终端、高频消息、多用户固定服务三个问题选择；填优势指标、适用条件、牺牲项和未选路线理由。其它合格组合全部列比较矩阵和附录；不合格与未实现路线也保留状态。不按队员分席，不预锁 LATTE/Falcon，不用教学配置填第三席。

## 5. 支撑材料索引与收件模板

每批材料归 `docs/research/team-<a|b|c>-delivery/<批次>/`，未来最终索引由 T9 汇总。原始大产物可以用外部包，但必须有清单/摘要/哈希/版本/取得方法；只给本机路径不算可移交。

| 类别 | 逐批收什么 | 复核人 |
|---|---|---|
| 原文与来源 | 原始 PDF/DOI/作者稿、题名/年份、取得方式/指纹，引用位置 | owner，统筹检查引用 |
| 源码与许可 | 上游提交、LICENSE、构建步骤、vendor/patch、依赖版本 | C 维护外部清单，统筹审包 |
| 参数与条件 | 完整数值/取整/分布/失败界，原文条件、估算器版本/命令和结果 | owner，独立数学复核 |
| 功能/攻击 | 原语/配对的实际命令、收据、负控、已知失败/跳过、源版本 | 统筹与 owner |
| 性能与图表 | 原始样本、实验元数据、可重画数据、图表及统计口径 | owner，统筹同口径检查 |
| 使用与演示 | 运行说明、演示配置/脚本、截图/录像、故障恢复、问答 | 统筹与队长 |
| 发布与复现 | 干净机器结果、源/作品版本、公开产物 SHA、PR/bundle 清单 | 统筹 |

收件行模板：`材料ID | 类别 | owner | 源提交 | 文件/外部包 | SHA-256 | 原文位置/命令 | 实际状态 | 关联case | 限制/下一步`。

发布包不得含主私钥、运行私钥、生产种子和运行状态；固定测试向量单独标明测试用途。先逐批保管材料，不等最后补写参数/环境。最终源代码、展示、报告、PPT、支撑索引与演示配置对应同一冻结版本。
