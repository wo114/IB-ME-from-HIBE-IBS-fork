## 1. 对此前组合范围的修正

此前“4套主比较+1个环探索位”是控制前期研究规模的建议，不是限制最终平台只能使用这些固定组合。最终成果应有：

- 能独立选择的HIBE和IBS组件，以及其具体算法/版本；
- 明确登记并通过验证的可用组合与参数配置；
- 三组针对不同场景的推荐预设；
- 其它方案的文献、单体、失败条件或已完成组合比较材料。

不要求17条候选全部实现或全部交叉。先做少量合格组件；通用协议复用，新增组件优先用已有伙伴接入。若界面公开支持某一交叉组合，就必须实际完成该组合的生命周期/攻击回归与对应参数测量。单体通过或相同接口不能替代组合验收。

例如两种HIBE和两种IBS均适配时，平台可以登记四个交叉组合。这需要四个原语的独立实施及四个组合的集成/测量，通常不需要重写四套通用协议或重新证明四套基础构造。

## 2. 选择流程和当前分类

建议流程：HIBE困难问题分类→具体HIBE方案，IBS困难问题分类→具体IBS方案，随后选择可用参数配置，查看已有实测或启动受支持的本机测量。无法接入的组合显示具体原因，不自动切换到其它算法或降级参数。

| 分类 | 当前项目中应如何解释 |
|---|---|
| HIBE：LWE | CHKP-ROM、ABB10-ROM为不同算法；目前可运行研究组合的ABB教学实现与论文忠实后端分别登记 |
| HIBE：RLWE | 有LATTE等调查/比较材料；需要两层匿名性、真实委派/采样和接口验收，当前不作为已可用选项 |
| HIBE：MLWE | 尚未确定符合组合条件的完整原语；需独立方案来源/实现，不能由矩阵替换或Luo模格IBS推定已有 |
| IBS：MSIS | Luo模格有实际四算法、研究参数与协议研究接线；完整组合同时含HIBE的LWE及IBS的MLWE/MSIS依赖 |
| IBS：NTRU结构路线 | 需有满足身份签名条件的具体原生IBS或经核验的转换；普通Falcon本身不是IBS，实际安全假设以具体论文为准 |
| IBS：其它已调研类别 | SIS、Ring-SIS、其它模格IBS可按实际完成度加入，保留所有依赖和模型信息 |

分类不是密码算法的完整身份。模块秩1等与环问题重合的情况注明，不通过改标签增加假设种类。混合组合分别记录HIBE/IBS依赖，不能称一个LWE+MSIS混合实例为“纯MLWE平台”。

此前建议主要在HIBE端比较两个LWE算法，尚未覆盖老师示例里的RLWE/MLWE HIBE选择。后续结构化HIBE调查应补这个缺口，但示例不是要求强行填满全部分类；当前先完成第一套真实系统。

## 3. 组合及状态登记

每个组合至少保存：

1. HIBE/IBS算法ID、论文/实现版本及分别列出的假设/模型；
2. 两个组件的独立参数profile ID/版本、采样实现与公开资源约束；
3. Wang协议、HYBRID/完整字节认证及序列化版本；
4. 外部身份/消息上限、底层身份编码、种子容量和完整签名载荷可行性；
5. 固定密钥/接收状态、恢复、四种匹配及伪造/接收者重签/篡改/解析测试证据；
6. 参数条件与经典/量子攻击估计及其明确适用范围；
7. 对应的完整运行数据及源代码/参数/环境指纹。

状态分开登记“候选资料”“组件实验”“完整研究组合”“参数条件已核验”等，不通过一个布尔开关或方法存在性授予安全等级。研究演示可以展示教学参数的性能，但清楚标明教学/研究性质；当前没有可以标为正式安全实例的配置。

已有BaselineIBME允许HIBE、IBS使用独立参数，模数无需相等；这支持模块化组合。能否开放一个具体组合还取决于论文/模型、身份与载荷、持久状态和实现条件，不能只检查两个方法签名相同。后端继续只通过公开接口互操作，不读对方内部密钥/矩阵。

算法/参数选择必须关联一套独立密钥上下文和状态。参数或组件切换不能继续使用原密钥/缓存；密文加载不猜测或回退格式。需要扩大载荷、修改绑定/wire或改变随机性复用时，另行在IMPLEMENTATION_SPEC冻结并验收，不把界面切换当作协议语义批准。

## 4. 安全目标与推荐参数

“目标128bit”“某工具的启发式攻击成本估计”“原文结论适用”“整体推荐参数”是不同信息。界面只开放实际已有的配置，目标档案必须配实际维度、模数、分布、范数/宽度、查询规模、统计/失败预算和估计工具版本，不按单个维度或测试次数命名等级。

分别显示隐私相关的HIBE条件与认证相关的IBS条件；整体声明还须计组合、归约/查询损失及实现差异。不能从较强组件继承等级，也不能仅取两项估计的最小值就认为完成整体证明。ROM、QROM、标准模型分别记录；一个组件的QROM或标准模型结果不自动升级组合。

未完成条件的profile只显示“研究/教学参数、目标或估计未核定”，不作为正式推荐安全参数。当前首套n=1公开恢复反例和其困难维度限制仍需解决；采样TV或正确相位不能变成128bit等级。

## 5. 最后返回的性能结果

| 指标 | 必要边界 |
|---|---|
| Setup、发送/接收发钥、委派 | 首次/重复身份及持久化恢复分开 |
| 完整Encrypt/Decrypt | 计入约定的IBS、HIBE、DEM、字节认证和序列化；冷/热分开 |
| 公钥、主/用户私钥、签名、完整密文 | 以实际wire为准，bit和byte区分；参考格式与压缩格式注明 |
| 内存、失败/中止、采样重试 | 记录完整后端资源，不能仅用Python分配或成功批次代表整体 |
| 参数与环境 | 消息/身份长度、次数、中位数/分位数、CPU/软件、工具版本、源/参数指纹 |

已有测量和本机新测明确区分；论文作者结果、公共计数和本项目实测分别显示。没有数据时显示未测，不填写0、插值或用普通签名库的跑分代替完整IBME。不同等级/模型/输入或机器的结果不能直接作快慢排名。

三个场景推荐预设分别考虑带宽/终端资源、在线高频消息、多用户固定密钥服务。预设来自实测权衡，不取代独立选择，也不预定算法赢家。组合优化仍须同目标基线和消融，子组件更快不直接等于完整A+B<C。

## 6. 实施顺序及本次边界

1. 先按[首套关键路径](../2026-10-10/首套系统关键路径与优先级.md)解决CHKP实际困难维度/采样资源、同组生产链、完整后端与组合攻击验收；Luo模格作为已有研究IBS。
2. 首套可运行后，将真实配置和测试/测量结果接到组合登记与展示层；先有一条可信数据链。
3. 新增原语时复用协议、状态/测试/评测框架，逐个登记实际兼容配对；RLWE/MLWE HIBE及NTRU结构IBS以具体论文和实际结果决定，不为了填满下拉框造方案。
4. 有可比组合后，选三组场景代表和推荐参数，再开展联合优化与完整展示。
