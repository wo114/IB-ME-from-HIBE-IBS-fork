# ABB10 与 CHKP：接手任务及验收标准

2026-10-18，按队长新指令发布到远端 main，供分别承接 ABB10 和 CHKP 的 AI 使用。基线为 main `2fccb0871d9b68c11c1e80828fabf154496de6df`；开始工作前拉取最新 main 并记录自己的基线。当前排序仍只由 [PROJECT_STATUS](../PROJECT_STATUS.md) 发布。

先读 [AGENTS](../../AGENTS.md)、[架构](../../ARCHITECTURE.md)、[实现规范](../../IMPLEMENTATION_SPEC.md)、[协作流程](../../AI_WORKFLOW.md)、[任务模板](../../DELEGATION_PROMPTS.md)及本文所链专属契约。沿用 Wang 两层匿名 HIBE + IBS，身份顺序为 `(rcv, phi)`。理论以原文引用和已确认工作假设为依据，不新增基础安全/匿名证明、逐个 hybrid 或完整归约任务。三条储备路线和增强隐私继续暂缓。

## 2. 所有接手者使用同一验收表

四个结果分别记录：**数值参数候选、完整真实运行、演示适用性、正式安全元数据**。它们不互相授予，不增加新的算法计数。

| 项目 | 必须交付的证据 | 不通过或未知时如何处理 |
|---|---|---|
| 论文/算法与参数 | 固定论文版本、算法位置和实现变体；同一组完整 n/q/矩阵宽度、采样/噪声/范数、身份/消息及服务规模；说明舍入和单位 | 不能将不同配置的宽度、估计、运行阶段拼成一个成功配置 |
| 已知不安全情况 | 保留原小参数的恢复/伪造负控，检查新参数的廉价结构性问题及必要方程/范数条件 | 已确认可廉价恢复或伪造的配置不能作为安全代表；脚本未成功不等于无已知攻击 |
| 困难性比较 | 沿用原定 **128 的比较模型筛选门槛**；根陷门恢复和密文困难性分别建模，经典/量子分列，给估计器提交、完整输入、方法和结果，优先选择有余量者 | 方法不适配、未评估、报错或无有限返回均明确说明，不记为安全成本无限大。已有 primal/dual 结果不是全部攻击已覆盖；模型成本也不直接等于完整 HIBE 安全位数 |
| 正确性与采样 | 核对同组两级委派、原像范数与相位/噪声；保留真实 Gaussian 和完整扰动、无偏模映射、失败预算及实际运行范围 | 不以降低噪声、删掉扰动或放宽验签/范数制造可运行性；数值估计和条件概率指数分开，不开展新基础证明项目 |
| 密钥隔离与表示 | 公共协议只走公开接口；父钥独立、无根秘密引用；紧凑/分块/外存表示保持数学对象和随机语义，参数及wire显式版本化 | 不能通过保留主陷门、重建时重新发钥或省略检查换取恢复成功；旧状态不静默迁移 |
| 完整原语与组合 | 同一目标配置实际根→父→叶→32 B KEM/载荷；再配一个已就绪 IBS，走公共 Hybrid/BYTEAUTH，完成真实 IB-ME 与恢复 | 组件、预检或 mock 只记对应范围；不能当作目标配置完整加解密 |
| 功能与状态 | 同根两接收者×两发送者；诚实路径、三种错配；签名/密文修改、截断/追加/重复字段；规范对象、参数/公钥绑定、固定发钥和新进程恢复；按层解释原始CPA行为 | 保存首次失败与pending，不自动重抽失败地址；公开支持的配置须有自己的组合验收 |
| 测量与比较 | 首次、热运行、缓存、恢复分别计时；实际 mpk/发送钥/接收状态/完整密文及持久对象大小、进程RSS；完整配方、输入、RNG、CPU/内存/OS/Sage、次数、超时、源码指纹 | 无实测留 null，不能把投影写实测；失败不能从样本中删除，历史记录不重复计本批 |

估计方法的性质参见 [lattice-estimator 官方说明](https://github.com/malb/lattice-estimator)：它用于比较抵抗已知方法的具体成本，并依赖启发式模型。主代表不因估计值刚过128就自动通过；不声称 NIST 等级或获得标准认证。继续保留 `security_claim=none`、`backend_admitted=false`、`parameters_are_formal=false`；需要调整正式元数据时由统筹依据既有含义单独审查，不能用工作前提或本文授权直接改值。

低于原目标的中间研究档可以运行和发表资源折中结果，但明确注明未达目标，不静默降低原定筛选门槛。已知不安全小参数仍是功能/负控成果，不补进目标参数完成名额。

## 3. 输入、测量和资源约定

- 与现有完整基线对齐：外部发送/接收身份各64 B，Hybrid内层编码各86 B，底层种子32 B，应用消息先32 B；通过实际容量预检后补1 KiB。原语和包装的输入长度分别记录。
- 完整性能基线目标为3套独立系统状态、每套3对warm和新进程恢复；昂贵配置先交一套真实完整生命周期，再在预算允许时补重复。单次成功可算运行证据，不能冒充完整重复基准。
- 热完整加密/解密以每次5秒以内作为**演示工程目标**，不作为密码学门槛或通用算法淘汰线。离线初始化/发钥可以是分钟级，允许现场从保存状态恢复；时间成本与摊销单列。
- 本机/WSL、较大内存服务器分别记录部署条件。需要更大内存不淘汰算法；服务器档须有该环境真实运行才能记为已完成。父陷门字节、同时存活对象、工作区与实际RSS分开，不能只看编码文件尺寸。
- 首批默认单次实验300秒上限、预先声明RSS和熵/工作区限额，分阶段记录。更长任务先写清新的预算、硬件、停止条件与预期产物并由统筹协调；不自动无界加时或启动高维长采样。停止后保留结果/失败/pending，不靠重启丢弃失败。
- 使用 WSL `~/miniconda3/envs/sage`。可移交脚本用 `~`；不要改用户WSL配置，不占用其他成员正在测量的资源。CPU/内存性能测量串行，独立代码/参数分析可并行。

## 4. 分别交给两位 AI 的首批任务

### AI-ABB：ABB10 固定维度路线

1. 从[算法与参数规范](../research/2026-10-04/ABB10两层HIBE算法与参数规范.md)和已有18行ABB高维公开筛查开始。把宽度/噪声/模数/困难性互相制约的具体原因列成同组参数卡，不重复生成n1。
2. 先选择一个能改变结论的已有方法：文献支持的较紧界、保持语义的根/约化实现、精确算术/基表示或对象存活改造。方法有出处，说明为什么适用于当前变体；不静默换成标准模型或另一HIBE。
3. 先公开计算同组资源与正确性/困难性，再只对合法且预算可承受的输入实跑。不得仅放宽 n、矩阵或对象上限。
4. 如得到目标配置，交完整生命周期、公共组合及恢复；否则交实际实现/验证结果、最接近候选、失败条件和工程剩余量，不能只写“正式参数WIP”。

独占实现范围：`src/ibme/hibe/abb_rom/`、`experiments/research/abb_rom/`、明确认领的 `tests/test_abb_*.py` 和本次ABB交付目录。`src/ibme/lattice/matrix_sampling/` 中的具体共享文件先向统筹认领；不得同时修改CHKP文件或公共registry/CLI。

接手结果：已完成并修正[ABB噪声折中同组参数卡](../research/team-a-delivery/2026-10-18-abb-noise-tradeoff/README.md)。固定q208与实际有限CDF下，n9600起达到**密文侧**四模型128比较门；AP09根短原像／陷门恢复的条件式Euclidean SIS模型对四行经典、量子调用均无有限返回，按本表规则记未知，因此正式双侧候选仍为0。为避免未知项冻结工程研究，另设不授予安全、运行或后端准入的实现研究层：仅当密文侧达到128且根侧两个结果均明确为`no_finite_estimate`时进入，当前得到n9600/9728/10240三行。有限但低于128、报错、缺失或畸形结果仍拒绝。完整父基仍为1.49 PB以上、32 B原始密文104.9 GB以上；后续可用n9600作算法／表示研究锚点，但不得扩大guard、登记参数或改用MP12陷门。

后续核验已同步[ABB完整基表示准入报告](../research/team-a-delivery/2026-10-18-abb-basis-representation/README.md)到上游`/3`参数卡，并逐行绑定q、q_bits、五类候选摘要及研究层策略。上游3个实现研究候选继续有效，但当前`KernelBasis`／GPV／RandBasis／ToBasis消费者下，仅换精确分块或外存不能让它们运行：它不减完整基、公钥、密文或当前`m²/m³`访问量；seed重放和MP12替换也不保持本路线语义。继续时可直接用n9600研究有出处、无需展开随机化完整基且能重新映射分布与安全归约的ABB兼容算法，根侧正式估计并行补齐；资源否定报告不撤销研究资格，也不授予安全或后端准入。

### AI-CHKP：作者稿3m与高基数完整运行

1. 先核对PR45审查结论、待审PR48及已合入的高基数原型，列清 `chkp`、`mp12-structured-hg` 和独立radix KEM各自已接通的部分；PR45关闭分支只作历史参考，不重复实现其包装或AP09根。
2. 优先将大q/高基数根、完整扰动、独立父R、256叶、codec与真实KEM/公共HIBE后端接成**同一明确命名的实现变体**。普通完整基CHKP与MP12紧凑陷门变体不静默互换，根算法和参数各自对应。
3. 从已有66组研究候选选择，优先对照n4096/b4096/q93与b1024/q89的成本和资源；这些只是起点，不是已推荐配置。先验证小规模迁移和对象存活，再决定预算内的扩维；不得把n8成功外推成n4096完成。
4. 测完整加解密、状态恢复、时间和内存，核对所有3m叶坐标。不能删H块、缩成2m、保留根秘密供父钥使用或只隐藏公开数据来回避攻击。

独占实现范围：`src/ibme/hibe/chkp/`、`src/ibme/hibe/mp12_structured/`、明确认领的相关CHKP/MP12测试、独立probe和本次CHKP交付目录。`src/ibme/lattice/chkp/`、gadget等公共工具的具体文件先协调，避免与ABB共用采样器同时写入；公共registry/CLI/Hybrid修改由统筹串行接入。
