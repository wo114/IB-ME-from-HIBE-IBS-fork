# CHKP 公开研究后端契约

本文件约束 `src/ibme/hibe/chkp/` 与 `src/ibme/lattice/chkp/`；公共六方法及装配规则见[统一规范](../../IMPLEMENTATION_SPEC.md)，执行状态见[项目状态](../PROJECT_STATUS.md)。旧 T1–T4 报告是历史证据，不能覆盖此处明确的版本和字段。

2026-10-18 用户确认继续采用下述作者稿 `3m` 实现；出版版 `2m` 仅作版本与参数对照，不列当前后端改造任务。理论工作采用项目既定的安全性/匿名性工作前提及原文引用，后续集中推进同组参数、实际资源、完整运行与评测。

## 1. 算法及来源

| 阶段 | 此实现 | 原文对应及边界 |
|---|---|---|
| 根 | MP12 GenTrap：均匀 Abar、有限离散 Gaussian R，A=[Abar\|G−AbarR]；确定性转换为完整整数格基 | [MP12 作者稿](../../papers/2011_lattice_trapdoors_micciancio.pdf) Lemma 5.3、Algorithm 1。独立记录近均匀条件、有限采样误差与中止；维度小不代表 LWE 困难 |
| 一级 | CHKP ExtBasis 的隐式 SampleD，有限 K 次 RandBasis，完整 ToBasis，参数固定选择的 checked LLL | [CHKP 作者全文](../../papers/2010_bonsai_trees_cash.pdf) §3.3.1、§3.4；没有以 MP12 DelTrap 代替 RandBasis |
| 二级 | 最大深度叶：对 256 个独立索引目标分别运行 SampleD，固定缓存所有整数原像 | 同文 §5.1–5.3；不再 RandBasis，不要求目标数值互异 |
| 加密 | r 均匀取于 Zq^n；各噪声独立取 round(qX)，X 密度正比 exp(−πX²/α²)；共享前导、256 位终端 | 噪声宽度 α 不是标准差；实际有限分布、截断和质量量化另有误差账本 |
| 解密 | 每位最近中心解码；原始 CPA 数学层允许低位修改后仍恢复同值 | 规范 wire、Hybrid AEAD、IBS 和 BYTEAUTH 各自验收，不能要求 raw 数学层承担完整字节认证 |

有限 GPV 使用精确整数/有理 GS 和余类算术；标量分布由有界拒绝采样实现。所有生产随机字节从 `SecureRandom.read` 注入，测试固定随机源另标。证明型误差界不包含文件系统、任意坏熵源、ToBasis/LLL 的额外工程失败或侧信道。

有限标量平方宽度执行域现为`1..2^88`，由共同常量约束Gaussian和GPV；这不是安全等级或修改实际宽度的规则。每个宽度仍必须分别满足半径、区间精度、质量、尾部、拒绝次数、精确算术和随机带预算门。

### 1.1 出版版与当前固定作者稿的布局差异

当前实现和对象版本冻结于仓库内作者稿：深度 `t` 写作 `A0 || H(id1) || ... || H(id1,...,idt)`，所以两层 `(receiver,sender)` 的叶为 `3m`。但 EUROCRYPT 2010 出版版（`https://people.cs.rutgers.edu/~dc789/bonsai.pdf`，SHA256 `87b5bff448f4e653bb7959a62c2b56c03ca495076678014b5dc8b7c90a90442f`）§5.3 定义的是 `A0 || ... || A_(t-1)`，两层叶为 `A0 || H(receiver)` 的 `2m`，终端身份进入 `G(receiver,sender)`；Theorem 5.3 及其模拟器同样只使用 `dm` 和 `d−1` 个 H 前缀。仓库作者稿 SHA256 `b1d8a2ae0e9d4e5c9145bbc6dc864090605c12a5b76149aa0684d62a8815d2ce` 的 `(t+1)m` 定义与它自己的 `dm` 定理/模拟器不一致。

因此当前 `3m` LWE 叶不能直接继承出版版定理。论文的 `aid-ind-cpa` 表示 adaptive-identity IND-CPA；跨层匿名是另外的 LWE 伪随机填充论证，不能把缩写误读为 anonymity。现对象、wire 和历史实物不静默改版；出版版 `2m` 路线须使用新版本并重新验收。完整数值目标、来源指纹、归约账本和资源拒绝见[2026-10-17 出版版目标](../research/team-a-delivery/2026-10-17-chkp-published-target/README.md)。

### 1.2 2011 作者稿两层服务版本

新登记 `chkp-author2011`（`chkp-author2011-3m-v1`）与旧 `chkp` 并存。[逐步对应与实跑记录](../research/team-a-delivery/2026-10-18-chkp-author2011/README.md)是该版本的证据入口。两层服务在 `Setup` 即要求 `seed32` 模式；`framed32` 不属于此版本的一级能力。新版一级 `Extract` 同时保存可委派的 `2m` 完整父基和针对 `G(receiver,j)` 的 256 个固定原像；旧版一级仅保存父基。新版一级加密使用 `2m` 个真实 LWE 前导再附加 `m` 个独立均匀坐标，解密只使用前 `2m`。新版二级继续旧版 `3m` 全 LWE 与 256 个固定原像，一级和二级密文具有相同的外部长度与对象类型。

新版公钥、主状态、一级/二级钥和密文有独立外层 magic；内部仍共用旧 CHKP 的 `ROHIBEContext`、`SeedCapsule` 及其域和字节格式。这个版本化边界不意味着内部随机预言机另建一个安全域。`Setup` 当前由 MP12 GenTrap 转完整根基实现作者稿所需的抽象 `GenBasis` 输出接口；独立的 AP09 GenBasis 组件尚未接入此 HIBE 路线，不应称作逐算法 AP09 实跑。作者稿 Theorem 5.2 对 `dm` 的陈述与同稿 `(t+1)m` 构造相冲突，功能链完成不修复该定理，也不证明匿名性。

一级发钥和叶委派各地址只允许一次采样尝试，失败地址在主/父状态中保持占用。新版私密对象的声明预算为 64 MiB；选中 Hybrid 时，仅明确声明扩展预算的新版主状态和一级钥可使用 64 MiB 组件上限，旧组件仍保持 16 MiB，包装对象另有 80 MiB+1 KiB 上限。实际可发地址数仍受基状态 16 MiB、参数最多 8 地址、随机带及整个状态的容量门约束。裸快照不能阻止外部回滚。研究运行、安全参数估计和作者稿安全归约分别验收，标记保持 `none/false/false`。

## 2. 显式配置与消息路线

`CHKPParams` 是完整公开参数快照。当前 `research_params()` 固定 n=2、q=1099511627791、m=127、父维254、叶维381、K=382；公开根 GS 平方界1078992910，父宽度平方591288114680，叶宽度平方82903323983053440，qα=4，epsilon_bits=128。LLL 策略在参数中预先固定，不能看失败样本再更换策略重抽。

`checked` 后处理 v2 固定使用 fpLLL wrapper 的 δ=3/4、η=501/1000，无变换矩阵；随后用整数约减与精确有理算术核对 size≤1/2、Lovasz≥74/100、原封不动的 GS 上界。输入与输出均独立验证为同一公开矩阵的完整核格，故无需信任外部变换矩阵。原 v1 使用δ=.999；v2可能输出不同基，但同一确定性后处理同时用于实际/理想分布时，TV不会增加。后处理失败计为失败，没有按样本切换算法或重新采样。

后处理具体版本由执行源码提交区分；公开参数的`version`和`lll_policy=checked`未单独编码v1/v2。同一suite摘要不证明旧私钥由v2生成；对象加载只验证实现所检查的格、方程、GS及参数关系，不能追溯采样来源或所用LLL库版本。

- `seed32`：恰好32 B，供 Hybrid 使用；不直接装配 Wang signature/message 载荷。
- `framed32`：4 B 长度前缀、最多28 B 内容及零填充；可单体测试，统一装配仍须检查 IBS/包装完整开销，容量不足就拒绝。
- 身份最大86 B，Hybrid 外部64 B 的身份编码分别占86 B；身份顺序始终 `(receiver, sender)`。
- 原始胶囊固定3919 B。根/父/叶随机字节预算分别2^34、2^39、2^39 B，按消费计数，**不是预分配内存**；公开保守最坏数不是实测消费。
- 显式实现上限512维、每个主/父状态最多8个地址、私密 wire 上限16 MiB，可能先触发字节资源上限。

`security_claim=none`、`backend_admitted=false`、`parameters_are_formal=false`。当前 n=2 配置是能进行实际采样和接口验收的研究配置，公开小维攻击是必留负面对照。它不能作为具备保密性的比赛安全实例或生产部署参数；上述原文版本冲突也是独立的不准入原因。

共享装配另检查公开有限噪声支持和 `evaluate_noise` 的条件式解密充分条件，工程预算固定为 `error_bits=64`、`seed_bits=256`、`encapsulations=2^20`。其理想条件式并合上界2^-36依赖叶原像范数条件，不包含有限分布 TV、中止、文件系统或安全归约。它是当前组合的充分门槛，不是所有可能参数的必要条件；原语自定义诊断不自动通过组合门槛。

## 3. 状态、编码和失败

公钥、主密钥、一级密钥、二级密钥携带完整配置及公开 A0/H/G 上下文；私密整数不模 q 截断。胶囊只携带公开上下文摘要和必要尺寸。解析要求规范整数、正确方程、完整格、明确身份/类型、无追加或重复字段；加载不调用采样器。

同一主状态的一级地址、同一父状态的叶地址只允许一次采样尝试。成功复用，失败留下墓碑；同叶的256个原像整体成功才发布。部分实际基依赖的资源检查位于已占位回调中，拒绝同样留下失败地址，不能声称所有资源拒绝均无状态。

Python 对象的 in-memory 状态不自行保证磁盘事务。CLI 负责本地锁、采样前 pending、提交状态后发布、崩溃后保守阻止；见[状态契约](transport-and-state.md)。裸快照没有外部认证或反回滚，不能在克隆旧快照后声称同址全局只采样一次。

本轮研究实例曾在叶构造阶段因旧标量执行域拒绝，实测耗熵为零。[显式继续工具](../../experiments/research/chkp_resume_pre_entropy.py)仅接受该已诊断的失败及完整预检，保留源失败文件，并在唯一新目录逐字节复用成功主状态和缓存父密钥。它不调用根生成、父委派、LLL或叶采样，不放开常规后端的失败墓碑。源收据与新执行收据分开保存；这不是一般性的失败重试或防回滚保证。

## 4. 软件布局与复现

实现只从 `src/ibme/` 导入运行时。原 `experiments/research/first_suite/` 等旧入口通过模块别名兼容，避免维护两份采样器。原历史报告的源码指纹保留其原版本；移动文件不等于重跑旧实验。

纯配置、预检、公开攻击与部分编码测试可用普通 Python；整数格和采样运行在 WSL 的 `~/miniconda3/envs/sage`。装配在缺少 Sage 时明确拒绝，不退回 mock 或教学 HIBE。生命周期工具把私钥保存在忽略的 `test-results/` 专属目录；公开交付只保存脱敏收据、源码哈希和测试结果。
