# IBS 版本决策：Luo 模格版主线

> 范围澄清（2026-10-11）：下文“唯一 IBS/主线”仅指 Luo 负责人的当前工作线；不限制统一框架下其它 IBS 的独立实现。矩阵 Luo 扩参暂停保持。功能接入与正式安全准入分开，项目并行任务以 [PROJECT_STATUS](../../PROJECT_STATUS.md)为准。

日期：2026-10-11

## 决策

项目现在全面推进 **Luo 2024 模格版 IBS**，配置入口为 `luo-module-research`。Luo 矩阵版停止当前参数扩展，保留为比较材料和后续备选，不再占用当前实现、参数和性能核验主线。

## 决策依据

1. 矩阵版论文没有给出完整的有限 `γ1/γ2` 参数规则。
2. 已完成两轮参数筛选：第一轮 10 行、第二轮 6 行，均没有通过完整筛选。
3. 矩阵版在拒绝采样、公开 LWE 对照和 SIS 范数界之间出现结构性张力，继续盲目扩网格没有充分依据。
4. 模格版已有真实算法实现、参数格式、NTT/Hint 和协议研究接线，可以先形成可复核的研究基线。

逐轮证据见[DeepSeek 参数决策证据索引](evidence/README.md)。

## 适用边界

模格版当前是研究主线和可运行基线，不等于已经完成正式安全准入。后续必须继续核对：

- Luo §4 的算法、参数和 Table 1 对应关系；
- MLWE/MSIS 条件和估计口径；
- 固定身份密钥、缓存和重复签名语义；
- 与 CHKP 两层匿名 HIBE 的通用构造接口；
- 完整 IB-ME 的正确性、攻击验收和公平性能测试。

## 安全证明范围

本项目按用户和老师确定的口径，引用 CHKP、Luo 和 Wang 原论文已有的安全结果，不重新撰写两个底层算法的完整基础归约，也不把 Luo §4.4 的 sketch 补写成新的完整定理。我们的任务是：

1. 逐项核对当前代码和参数是否满足原论文条件；
2. 记录 SHAKE、缓存、固定密钥、BYTEAUTH 和编码等工程差异；
3. 说明 CHKP 与 Luo 如何满足 Wang 通用构造的组合前提；
4. 用参数估计、正确性测试、攻击测试和性能测量支撑实现结论；
5. 对原论文没有覆盖的内容明确标注限制，不额外声称 QROM 或完整形式安全。

矩阵版仍保留 `security_claim: none`，不删除已有实现和筛选记录。项目统一状态保持：

```text
security_claim: none
backend_admitted: false
parameters_are_formal: false
```

## 全面推进范围

1. 以 Luo 模格版作为当前唯一 IBS 研究后端，继续补齐论文 §4、算法、参数、编码、缓存和实现的逐项对应。
2. 与 CHKP 两层匿名 HIBE 的交接保持原安排：队友负责 CHKP 与格工具，主线在交接后完成接口接入和完整组合验收。
3. 继续由 DeepSeek 做论文来源、参数计算、攻击估计和报告的独立复核；报告必须区分论文事实、项目推导、启发式估计和未决假设。
4. 模格版先完成正确性、参数条件、MLWE/MSIS 估计和安全口径，再做完整 IB-ME 的攻击测试与公平性能测量。

## 下一步

1. 完成模格版论文条件—实现—参数对照；
2. 明确当前参数的安全估计和限制，不直接继承论文安全位数；
3. 等 CHKP HIBE 后端交接后，优先接入模格版 IBS 完成首套组合；
4. 在完整组合稳定后，统一测量尺寸、运行时间、内存和攻击验收；
5. 如模格版出现不可修复阻塞，再由老师或队长决定是否重新评估其他 IBS；在此之前不恢复矩阵版扩展。
