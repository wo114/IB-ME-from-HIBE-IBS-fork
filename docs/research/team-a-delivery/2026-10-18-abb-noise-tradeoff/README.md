# ABB-ROM 噪声折中与完整基资源结论

本批从主分支 `8cc69c7` 接手 ABB10 CRYPTO 2010 §4 ROM 路线，没有重复生成已知不安全的 `n=1/q26` 实例。新增公开筛查器把同一组 AP09 根维度、两层 BasisDel 宽度、ABB `q/5` 正确性界、实际有限舍入连续 Gaussian、固定 LWE 比较模型和对象尺寸下界放进同一张参数卡。

**结论：取得了数值参数推进，但没有取得可运行目标配置。** `n=9600/q208/qα=721` 是本批网格中第一个通过四个固定比较模型 128 门槛的点；`n=10240` 的最低结果为 140.450 bit，余量更大。然而单份完整父基的编码下界分别约 1.531 PB 和 1.742 PB，32 B 原始逐比特密文下界约 106.326 GB 和 113.414 GB。全部候选都被现行执行、对象和 Hybrid 容量门拒绝，不能生成根、私钥或完整 IB-ME。

## 同组参数与结果

固定奇素数

```text

bit_length(q) = 208
qα = 721
```

`qα=721` 是当前 `tail_bits=128`、`max_radius=8192` 下能容纳的最大整数宽度。实际构建的有限 CDF 半径为 8189、支持点 16379、每次抽样32 B，CDF SHA-256 为 `62d12dbf8d50678755d08254332505d5a83aaac1e472e9f7c227d7fbf61e314e`。没有用零噪声、均匀噪声或离散整数 Gaussian 替代论文的舍入连续 Gaussian。

身份长度为两层各86 B，载荷为32 B／256个独立加密比特，封装预算为 `2^20`，正确性尾界使用128 bit。以下成本来自固定 lattice-estimator `53da5982597709ba0fdf94ea37a84d822310fd84`，模型为 ADPS16 classical/quantum Core-SVP、primal-uSVP LGSA 与 plain dual：

## 实际执行与资源

正式公开运行一次，使用本机 Nix Sage 10.9／Python 3.14.7、Linux 6.18.56、12逻辑CPU；进程内总时长41.151 s，有限CDF构建0.855 s，进程最大RSS观测304632 KiB。运行只做公开整数／有理数计算、CDF构建和估计器调用：根、基、私钥、密文和身份矩阵生成数均为0，私有随机字节为0。

完整机器可读输入、四模型原始字段、错误状态、源码散列和对象下界见 [parameter-card.json](parameter-card.json)；测量摘要见 [runtime-summary.json](runtime-summary.json)。复现命令见 [commands.md](commands.md)。

## 实现边界与下一步

本批给 `abb_projection` 增加显式噪声宽度，并新增严格整数边界函数；默认旧筛查仍选最小 `qα>2√n`，旧参数和wire没有改变。真实 `abb-rom` 后端仍保持现有 `qα=4`、`n≤64`、维度≤1536和对象门，筛查结果不会自动进入registry、CLI或参数工厂。

当前主阻塞已经从“是否存在数值点”收敛为“ABB完整基表示和消费者必须展开完整基”。下一批若继续，应先给出有文献依据、保持 ABB BasisDel／SamplePre 分布语义的结构化、分块或外存表示，并证明消费者无需展开 PB 级完整基；不能只扩大维度／blob guard，也不能静默换成 MP12 G-trapdoor 后继算法。
