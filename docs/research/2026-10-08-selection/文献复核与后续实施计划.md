# 文献复核与后续实施计划

日期：2026-10-08。起点：`6fd7f42`，已同步队友的 IBE + IBS 研究归档。本文响应用户对证书式 ML-DSA/Falcon 工作量、HIBE 候选范围以及老师“安全性证明以引用为主”的反馈。它更新研究优先级，不改变 Wang 两层匿名 HIBE + IBS 的协议或放行任何安全后端。

## 1. 本轮结论

1. **优先寻找直接给出 IBS 算法和定理的论文。** 证书式 ML-DSA/Falcon 有通用转换依据，不能说没有理论支持；但它们增加转换、状态和模型适配工作，暂退为工程储备。之前把这两个候选排入前三，偏重了底层标准与库的成熟度，未充分体现团队现在的选型偏好。
2. **HIBE 不只有 ABB10。** CHKP 的 Bonsai Trees 给出了完整 HIBE，尤其值得比较其自适应 ROM 构造。旧调查把 Bonsai Trees 仅列为底层技术参考，遗漏了一个实际算法候选。
3. **安全工作的重点改为引用定理、核验适用条件、检查实现与选参。** 不再默认要求重新证明每个基础原语，或把完整 Lean 形式化作为工程推进的前置任务。已发现的具体问题仍须如实记录，无法直接引用的候选先降低优先级，而不是自动承担修补整篇论文的任务。
4. **先完成首套真实论文实例，再扩展和优化。** 已有采样、编码、生命周期和攻击对照继续复用；本轮没有新增密码后端、运行密码性能实验或选定生产参数，`security_claim: none`。

这里的“引用为主”是根据用户转述作出的项目工作解释，不等于老师已指定某一套新算法或认可某个参数集。

## 2. “只引用安全证明”怎样落实

我们交付的是已有构造的忠实实现与系统研究。Wang 的组合结论以及 HIBE/IBS 的原语结论可以引用已发表论文，不需要把所有游戏跳跃重新推导一遍。[W]

每个后端提供一张简明对应表即可作为理论材料的主要入口：

| 要说明的内容 | 实际交付 |
|---|---|
| 使用的算法 | 论文版本、章节/算法编号、对应实现入口 |
| 引用的结论 | 定理编号、攻击模型和结论范围；区分原文结论与本项目实现 |
| 组合的前提 | 两层、匿名、自适应、密钥复用、身份/消息空间和载荷条件 |
| 参数的合法性 | 采样宽度、范数、噪声、模数和失败概率条件的代入表 |
| 实际实现 | 随机数、采样方法、规范编码、库版本、测试及偏离原文之处 |
| 具体攻击成本 | 固定版本估计工具和输入；经典/量子攻击成本分别记录 |

可以减少的工作：基础定理的完整复证、没有新增算法语义的重复归约、逐层程序概率模型和 Lean 总包的进一步扩展。

仍要完成的工作：上述对应表、合法参数、真实原语、功能/负面测试、旧公开伪造和篡改回归、公平性能测量。这些是实施责任，不是另写一篇基础密码学证明论文。

有三类情形不能仅靠引用解决：

- 引用结论与实际模型不同，例如每次重新发钥的实验与固定用户密钥服务。
- 我们改动了密码算法，例如共享随机噪声、合并陷门、改变签名消息或增加认证包装。
- 已有明确反例或缺失前提，例如教学参数的公开伪造，不能被论文题名消除。

应优先采用原文已有的算法和优化。完整密文字节绑定是赛题的独立验收目标；若原组合没有给出这一结论，选用有明确依据的包装或提供局部说明，不把普通消息不可伪造引用成全部密文篡改拒绝。

## 3. 扩展后的 HIBE 筛选

筛选要求保持两层身份 `(rcv, phi)`、正确委派、自适应匿名安全和足够载荷。下表的“候选”不等于已完成参数与实现准入。

| 候选及原文入口 | 本轮核对内容 | 适合当前项目的用途 |
|---|---|---|
| ABB10，CRYPTO 2010，§4 | 固定维度委派的匿名 ROM HIBE；沿用已有算法规范 | 第一套基线候选，保留已有积累 |
| **CHKP / Bonsai Trees，EUROCRYPT 2010、后续期刊全文，§5.2–5.3** | §5.3 的 ROHIBE、Theorem 5.2 给出自适应安全；§5.2 说明匿名填充 | **新增的第二个完整 HIBE 优先候选**；比较扩展格基与固定维度委派 |
| CHKP 同一全文，§5.4 | Theorem 5.4 / Corollary 5.5 的标准模型自适应转换；固定两层与可容许哈希条件 | 标准模型研究储备；不是 §5.3 的参数替换 |
| ABB10，EUROCRYPT 2010，40 页全文 §8 | Theorem 33 证明的是选择身份 HIBE；§7 的自适应结论针对 IBE | 同源比较资料；不能把自适应 IBE 结论直接用于 HIBE |
| Latte，Zhao 等作者接受稿 | 完整实现、采样/精度和参数；安全分析以 ID-OW-CPA、ID-IND-CCA 等为入口 | 环格工程与委派性能对照；尚未核实符合 Wang 匿名定义的直接定理 |
| Goyal–Koppula–Rajasree 2025 | 已核对自适应匿名 HIBE 的原始摘要；匿名转换的公开材料涉及 lockable obfuscation | 理论储备；本轮未取得全文、没有工程准入或成本实测 |
| Zhang 等，Entropy 2020，§4 | 环格 HIBE 的公开算法、Theorem 4/5 和参数条件 | 先澄清算法类型，暂不承诺真实后端 |
| Zhang–Wu 2017、Singh 等 2012/2014 | 保留已定位的出版来源；本轮没有全文级新核验 | 后续资料候选，不能按题名自动批准匿名性 |

**CHKP 的具体价值。** 它通过扩展矩阵和随机化格基进行委派，原文同时给出完整 HIBE 与匿名化说明。ROM 路线的归约损失包含层数和预言机查询数；本项目只需要固定两层，不能把它描述成任意深度都保持相同效率。§5.1 还说明多比特封装的摊销，值得用于载荷成本分析。[C]

**需要保留的筛选区别。** CRYPTO 与 EUROCRYPT 两篇 ABB10 不是同一算法；EUROCRYPT 全文 Theorem 33 的选择性结论不能替代本项目要求的自适应结论。Latte 的公开实现并不自动提供这里需要的匿名定理。[E][L]

**2020 环格候选的实施疑点。** PDF 第 10 页 Derive 将私钥输出写为短向量，而第 11 页 Decrypt 将该对象传给需要陷门的 SamplePre；二层维度也需对应。Theorem 4 的模数不等式方向与邻近推导需核对。这里记录的是原文的类型/条件疑点，未声称已经攻击该方案；应找修订或解释后再实施，避免自行补写委派语义。[Z]

以上扩大了调查范围，但不能得出“有很多已经可用的高效匿名环/模 HIBE”。严格适配当前组合的候选确实比一般 IBE/HIBE 少。

## 4. 直接有论文支持的 IBS

| 候选 | 具体文献入口 | 优点与当前边界 |
|---|---|---|
| **Luo–Chen–Susilo–Huang 2024** | *Identity-Based Signature from Lattices without Trapdoors*，ICICS 2024；§3 Algorithms 1–6 / Theorem 1，§4 Algorithms 13–16 | 直接给出矩阵及模格 IBS；模格依赖 MLWE/MSIS，IBS 无需陷门原像采样；固定密钥模拟语义需确认 |
| **SRGG-IBS 2025，Jia–Liu–Tang–Wang** | *Constructing Efficient Identity-Based Signatures on Lattices*；Definition 3、§4 Algorithms 1–8 / Theorem 2、§5 | 原文明确缓存身份密钥，给出模格参数和 C 原型测量；原型代码本轮未找到公开版本 |
| **Yu–Liu–Li 2026** | *Identity-based signature and identity-based matchmaking encryption from lattices*，TCS；公开内容定位 IBS、§4.3/4.4 组合 | 针对固定密钥的标准模型 IBS；全文仍缺，不能据摘要写真实后端 |
| Foo–Li 2023 | 本地固定稿、已有研究规范与补充论证 | 保留研究积累和直接 SIS 方向；不把修补原证明与继续 Lean 扩展列为下一轮默认主任务 |
| Sageloli 等 2023 / Wang + Pan–Wagner | 已定位论文及前期审查 | 直接 SIS/Ring-SIS 算法储备；密钥复用模型和成本条件仍需区分 |

**2024 无陷门 IBS：值得做实施核验。** 模格版本有完整算法和参数表。不过 §3.2 Algorithm 6 调用 Extract Oracle，正文又描述重复取钥的缓存。下一轮须明确该调用是否使用同一缓存；不能直接把每次产生新用户密钥的模拟当作固定密钥服务结论。此处是待澄清的引用条件，未认定真实方案被攻破。原文的量子讨论也不等于已经给出整个 IBME 的 QROM 证明。[I24]

**SRGG-IBS：有直接论文，不是 Falcon 包装。** Definition 3 的取钥与签名查询复用已有密钥。Theorem 2 是带底层强不可伪造条件的 QROM 结论，引用时必须保留该条件。其具体实例在 §5.2 明确使用 MLWE/MSIS；Table 1 与 Table 4 的公钥、签名尺寸不一致，正式尺寸须按固定参数和实际序列化核算，不任选较小值。正文说实现将公开，本轮只读到论文，未取得该 C 代码。[I25]

**2026 IBS 与替代协议分开。** 独立 IBS 可调查是否接入 Wang 主线；整套 IBE + IBS 则是另一种组合。队友归档中的“方案③”不与原 Falcon 候选 C 共用编号；合并资料本身不改变当前主线。[Y26]

## 5. 三组组合如何重新组织

本轮先给出三个**待准入的研究组合**，用来组织工作；它们不是实测“最好的三套”，也没有已经安全的正式参数。每个组件都有直接方案论文，完整搭配仍由本项目按 Wang 组合定理实现。

| 工作组合 | 建议组件 | 希望体现的优势 | 实施前最先核对的条件 |
|---|---|---|---|
| P1：工程候选 | ABB10 §4 ROM HIBE + Luo 等 2024 模格 IBS | IBS 避免陷门采样，模块运算与拒绝采样适合工程实现 | 固定身份密钥的模拟/缓存解释、模格参数和编码 |
| P2：第二 HIBE 与采样路线 | CHKP §5.3 匿名 ROM HIBE + SRGG-IBS 2025 | 两个组件均有直接算法；比较扩展委派、原像采样及离线/在线优化 | 两层 HIBE 参数、匿名填充、SRGG 底层定理条件和尺寸核算 |
| P3：固定密钥理论对照 | ABB10 §4 ROM HIBE + Yu–Liu–Li 2026 IBS | 引入直接标准模型 IBS，比较固定密钥与 PRF/电路求值的成本 | 取得目标全文，核对实际算法和有限参数可执行性 |

P1 的条件未澄清时，先采用 **ABB10 + SRGG-IBS** 作为首套候选的替代，不为凑数量写一个缺少依据的适配证明。P3 缺全文时不妨碍已取得算法的工作，也不以旧 IBS 代替后声称复现该论文。

这个安排涉及 **两个优先 HIBE、三个 IBS 研究方向、三个组合任务**。它不是三种 HIBE；P1/P2 的 IBS 都有模格依赖，算法不同不等于新增困难假设。P3 的 SIS/PRF 依赖以全文为准；独立 Ring-SIS 完整实例仍在 Sageloli 等储备路线中，不能宣称环、模、矩阵三类已经全部实现。

P3 的 IBS 即使有标准模型结论，与 ROM HIBE 组合后也不能称整个 IBME 为标准模型方案；同理，一个 IBS 的 QROM 结论不能自动升级整个组合的模型。

## 6. 接下来做哪些工作

按交付物推进，不按截止日期省略研究；每次只完成一个可审查边界。

| 阶段 | 要完成的工作 | 这一阶段结束时拿到什么 |
|---|---|---|
| **下一轮 R1：实施规格与首套选择** | 写 ABB10/CHKP 两层的算法、引用与参数对应；完成 Luo 的缓存语义核验及 SRGG 的底层条件/尺寸核算；选定首套与备选 | 具体算法—接口对应表、参数条件表、来源版本、首套后端任务书；不要求重新证明完整安全定理 |
| R2：首套真实原语 | 按 R1 选定论文分别实现 HIBE/IBS；先独立 contract tests，再接固定用户密钥、多消息和持久化 | 真实的小参数研究实例、规范测试向量；合法参数另列，教学实例不宣称安全 |
| R3：完整首套 IBME 与漏洞回归 | 接 Wang 构造；恢复四种匹配、恶意接收者自我伪造、公开线性/LLL 对照；实现有明确依据的完整性包装 | 可运行首套、旧反例的回归结果、包装的性质与局限 |
| R4：算法及困难假设扩展 | 复用接口加入第二 HIBE、其它直接 IBS；获取 Yu 全文；评估独立 Ring-SIS 方向 | 分别统计困难假设、算法和完整组合；失败或未准入实例单列 |
| R5：组合优化与公平实验 | 在真实原语上做联合载荷/参数、已有上下文复用、文献已有多比特摊销和合格缓存；比较原版与逐项优化 | 完整 Enc/Dec、尺寸/内存/失败率的同条件基线及消融 |
| R6：竞赛交付 | 系统演示、场景、研究报告、引用链、可复现实验、明确限制 | 老师和评审可运行、可核验的系统与材料 |

**下一轮不继续默认扩展 Foo–Li 的 Lean 总包或另写 QROM 归约。** 已有工作留作研究资产；若选定方案存在未被已有定理覆盖的具体差异，再单独评估少量补充说明是否值得，不能无限扩展证明任务。

R1 不是继续泛泛收集论文：必须输出可供实现的四个原语规格、明确首套选择，以及每项尚缺材料。拿不到的全文写明，没有算法就不实施那个后端。采用 Sage 时使用 WSL `~/miniconda3/envs/sage`。

组合收益统一按成本计算：

$$C_{\mathrm{optimized}} < C_{\mathrm{baseline}}.$$

比较采用相同安全目标、消息/身份、库版本、随机与计时边界。文献已有摊销、通用转换和缓存不直接宣称密码学原创；本项目贡献可以是联合选择、具体工程优化、完整系统和可复现证据。完整性包装若改变密码语义，仍需对应依据，不能靠“引用原组合”免除。
