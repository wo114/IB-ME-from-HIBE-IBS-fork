# Luo 单体：发钥、恢复、签名与尺寸检查

这轮解决的是：**Luo 单独拿出来，能否连续使用、恢复后继续使用，以及真实要存多少字节。** 不再重复慢速教学HIBE全链路，也没有改Luo算法、默认参数或签名格式。

## 1. 已经做完什么

- 3个独立测试系统，身份长度1/5/64 B，IBS消息长度0/256/4096 B，每格2次签名：共 **54次正常调用、528次内部尝试、0次正常中止**。
- 每份数学签名分别用reference/compact编码、加载、验签，共108次编码、108次加载、108次验签，全部通过，数学字段和规范字节往返一致。
- 每个身份首次发钥后检查缓存；用“一旦读取随机数就报错”的随机源确认缓存不重新发钥。每格第二次签名使用从主状态快照恢复后取出的密钥，不只是检查“能读取文件格式”。
- 实测0/1/3缓存条目的主状态尺寸、三种身份长度的独立密钥尺寸；快照只在内存中流转，不把私钥、随机带或签名字节写到证据目录。
- 本轮选定回归 **212 passed，19.27秒，退出码0，无失败/错误/跳过**。包括49项新生命周期/实验账本检查和既有163项Luo相关测试；不是全仓库或CHKP验收，也不能与上轮317项直接相加。

## 3. 时间怎么看

单体Setup中位数0.1724秒（3个系统）。下表是Sign中位秒数，每格6次观测（3系统×2次），包含算法内部自验，不含编码：

| 身份长度 | 消息0 B | 消息256 B | 消息4096 B |
|---|---:|---:|---:|
| 1 B | 0.4733 | 0.5742 | 0.5711 |
| 5 B | 0.4558 | 0.9123 | 0.7645 |
| 64 B | 0.4215 | 0.8526 | 0.3525 |

重试次数会影响时间，样本量小；上表不能解释成“消息越大越快”或一般算法排名。缓存取钥只计缓存调用，字节一致性检查在计时外；冷发钥、恢复、两格式编码/解码/验签的分组数据在 [summary.json](evidence/final/summary.json)。

最终批次墙钟60.116秒，420条阶段记录。Windows工作进程生命周期峰值WorkingSet为63885312 B（约60.93 MiB），包含解释器、导入和证据对象，不是纯算法内存增量，也不是单次Sign峰值。

环境为Intel Core Ultra 7 255HX、20逻辑处理器、约31.36 GiB物理内存；Python/Windows版本见元数据。没有锁定CPU频率/亲和性或控制全部外部负载，不与别的机器直接排快慢。测量使用可复现的公开测试随机流，不用于真实秘密；未重新评估生产熵或侧信道。

## 4. 返工与独立复核

DeepSeek先给出驱动和候选实验；独立审查发现其异常时可能漏记整组call、缓存阶段测量/恢复对象使用、完成标记和源码指纹等问题。主Codex另写精简版，不将活动草稿直接入库。

主Codex首次54次成功批次保留在 `evidence/pre-abort-fix/`。随后故障注入测试抓到“中止调用有事件耗时，但call表漏填耗时”，见 `evidence/pytest-first.xml`（203通过、1失败）；修复后重新运行全部54次及205项选定回归。最后补上7项Setup、恢复和尺寸账本缺失/篡改检查，选定回归达到212项通过；最后这7项不需要再重跑密码实验。首次成功数据不混入最终统计，失败日志不删除。

DeepSeek第二十一步对代码和初始完整批次作只读回核，最终收据另作补记；它没有重新跑密码实验或pytest。与主Codex不同的独立审查结论分别记录，不把审查意见全当事实。详见 [验收收据](验收收据.md)。

## 5. 完成边界与下一步

**Luo单体本轮生命周期、尺寸和实现证据可以交接。** 恢复测的是内存序列化/反序列化及密钥方程核验，不包含磁盘事务、硬断电、防回滚或独立旧快照同步。

参数和论文对应见 [参数与引用边界](参数与引用边界.md)。真实LowBits联合概率、总Sign中止界仍未知；测试不能替代安全证明。保持 `security_claim: none`、`backend_admitted: false`、`parameters_are_formal: false`。

下一主要工作是CHKP实际后端到位后的同版本组合验收，不为已有Luo单体再循环增加相同审查轮。正式参数/安全声明以及多算法横向比较、系统展示仍属后续项目工作。4096 B是本轮IBS原语输入，不是完整IBME的3924 B应用上限；本轮没有测CHKP或完整IBME性能。

## 6. 复现入口

仓库根设置 `PYTHONPATH=src`、`PYTHONDONTWRITEBYTECODE=1`，运行：

```text
python -B experiments/research/luo_lifecycle_benchmark.py --output outputs/luo-lifecycle-new
python -B experiments/research/audit_luo_lifecycle.py docs/research/2026-10-11-luo-lifecycle/evidence/final --run-id codex-final
```

输出目录必须不存在。正常中止记录在调用表中，中断会留下未完成证据；未知指标不填0。批次有协作式30分钟检查，本轮实际命令还用外部`subprocess.run(timeout=1800)`约束整个工作进程。原始CSV、metadata、summary、JUnit和文件哈希清单都在 `evidence/`；[结果卡](结果卡.json)供后续展示层读取，不注册安全后端。
