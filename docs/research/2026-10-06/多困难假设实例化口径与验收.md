# 多困难假设实例化口径与验收

日期：2026-10-06。任务边界：落实用户关于多实例按不同困难问题组织的决定，修订研究范围、验收与汇报口径。本次没有选择新的具体原语、运行密码实验或修改代码/参数。现有演示与研究参数保持 `security_claim: none`。

## 1 已确认范围

通用构造仍为王老师的两层匿名 HIBE + 自适应安全 IBS，不实施 Boyen–Li 增强隐私。多实例的主轴是不同格困难假设；同一假设下的算法选择用于完成该路线，算法对照不代替困难假设扩展。

每套组合分别登记 HIBE 和 IBS 的假设依赖。普通矩阵 LWE/SIS、Ring-LWE/Ring-SIS、Module-LWE/Module-SIS 是研究分类；这些问题之间有关联，不宣称它们彼此独立，也不据此宣称多假设冗余安全。[LPR][LS]

赛题 R2 允许不同假设或不同方案，并明确至少一种 LWE/SIS 完整实例；本项目按用户决定提高研究目标，优先不同假设。矩阵、环、模三类是研究方向，不是赛题强制完成三套的要求，也不表示现有三套已准入。[赛题原文摘录 R2/R5](../2026-09-30/IBME-赛题验收基准/2026-09-27/赛题验收基准.md)

## 2 怎样计入完整实例

| 工作 | 项目中的归类 |
|---|---|
| 同一 LWE HIBE 分别配 Foo–Li SIS IBS、Wang + PW SIS IBS | 同一矩阵 LWE/SIS 路线的算法对照；不计两个困难假设实例 |
| 同一方案调整 n、q、宽度、安全目标或消息长度 | 参数扫描与性能分析；不增加假设类别 |
| 更换 MP12 采样实现、在线高斯或 gadget 底数 | 组件实现/优化；不自动改变困难假设 |
| LWE HIBE + 满足组合前提的 Ring-SIS IBS | 引入 Ring-SIS 的新假设组合；标注为矩阵/环混合 |
| 满足组合前提的 Ring-LWE HIBE + Ring-SIS IBS | 环格组合；须先完成两种身份原语的准入 |
| 满足组合前提的 Module-LWE HIBE + Module-SIS IBS | 模格组合；须先完成两种身份原语的准入 |
| 只有环/模矩阵、乘法、采样或签名方程演示 | 组件研究，不计安全完整 IBME 实例 |

更换原语后仍需完成整个协议验收。接口可切换但没有算法/定理映射、合法参数、固定密钥模型与端到端实现的候选，只能登记为待核验，不能计作安全完整实例。

环/模迁移必须写明环、多项式、次数、模秩、分布、范数与具体困难假设；不能仅把整数矩阵换成多项式，就沿用矩阵 SIS/LWE 证明。模秩 1 等与环问题重合的特殊情况需说明，不以重新命名增加假设类别。[LS]

## 3 路线与优先级

| 路线 | 拟核验的假设依赖 | 当前状态与下一工作 |
|---|---|---|
| 首套矩阵格主线 | HIBE：LWE；IBS：SIS | ABB10、Foo–Li 为当前参考候选；继续完整有限参数与成本审计，不因范围修订默认转向另一套 IBS |
| 环假设扩展的过渡组合 | HIBE：LWE；IBS：Ring-SIS | 已有 Sageloli 等完整算法研究入口；核验固定密钥复用、环采样、合法参数及成本后决定是否接入 |
| 完整环格研究方向 | HIBE：Ring-LWE；IBS：Ring-SIS | 两层匿名、自适应 HIBE 尚未选定；先做原语论文准入，不能把普通匿名 IBE 或普通 HIBE 直接接入 |
| 模格研究方向 | HIBE：Module-LWE；IBS：Module-SIS；必要时先形成如实标注的混合组合 | 具体身份原语尚未选定；先调查完整算法、定理、参数和实现材料，不直接把 ML-KEM/ML-DSA 当作 HIBE/IBS |

环/模方向先完成论文本身的算法与证明核验、固定密钥模型适配和有限参数分析，再决定实现范围。现有 Ring-SIS 候选的具体尺寸与查询损失尚未解决，不能只因结构化格名称就预设更快、更小。[既有候选核验](../2026-10-03/原语选型第一轮核验.md)

同一假设下的算法对照可帮助判断首套原语、参数损失和优化，但不再并列成多困难假设交付目标。当前单项下一任务仍为 Foo–Li 完整有限参数可行性及成本审计，详见 [进度入口](../../PROJECT_RESTART.md)。

## 4 每套完整组合的验收材料

1. **依赖表**：分别记录隐私、匿名、认证、完整性依赖的困难假设、其他计算假设和证明模型；ROM/QROM/标准模型不得混用。
2. **原语表**：固定论文版本、算法/定理位置、两层委派与匿名定义、自适应发钥和签名游戏、持久用户状态与规范编码映射。
3. **参数表**：记录维度、模数、环次数/模秩、秘密与误差分布、采样宽度、验证和归约范数、查询上限、统计与失败预算。
4. **难度与资源表**：固定经典/量子攻击模型及工具版本；结构化攻击另列。记录密钥/签名/密文尺寸、采样和委派成本、峰值内存、随机带需求。
5. **完整协议结果**：通过四种身份匹配、伪造、自我伪造、密文/签名篡改、解析异常和批量正确性验收，认证包装单独论证。
6. **公平评测**：尽量统一安全目标、查询规模、输入、机器与测量方法；证明模型或功能不同的结果明确标注，算法对照和参数扫描分别报告。

接口字段、参数类型和序列化格式在具体原语选定后再按 `IMPLEMENTATION_SPEC.md` 版本化冻结。本次不新增一个未经准入的环/模配置，也不注册正式后端。
