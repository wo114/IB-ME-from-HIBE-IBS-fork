# SRGG serial runtime evidence for original Table 4 rows (WIP)

This package measures the standalone Python/Sage `SourceSchurBackend` at the original Table 4 `n=512, p=16383, b=31, w=2, Q=15744063, d=2/3/4` inputs. It uses the explicitly labelled table-standard-deviation interpretation, one fresh `SecureRandom` setup/key/sign lifecycle per cycle, three cycles per profile, a 5-byte Alice identity and 32-byte message, and 1000 additional verifications of the last honest signature. All honest checks passed. The frozen source is Jia et al., *Constructing Efficient Identity-Based Signatures on Lattices*, [PDF](../../../../papers/2025_efficient_ibs_jia.pdf), SHA-256 `258583c5b90255afe91343a282cb62840198b1192b6462dfc9597a24f8c01152`.

The [Chinese report](README_zh-CN.md) records local wall-time medians, whole-process peak RSS, method and limitations. Full per-call wall/CPU timings, retries, sizes and environment are in the three `param-*-table-sd.json` receipts. The [source](../../../../experiments/research/candidates/srgg/paper_runtime_benchmark.py), [tests](../../../../tests/test_srgg_paper_runtime_benchmark.py), [validation](validation.json), [manifest](MANIFEST.json) and [verifier](verify_delivery.py) make the package reviewable.

This is not the authors' C/gcc 8.3/Deepin 1000-run median, rANS size, equivalent hardware, or an isolated CPU benchmark. Repeated verification reuses one signature. No C/rANS code or frequency table was available locally. Three Python/Sage cycles cannot be presented as an author-performance reproduction or fair cross-implementation comparison. There is no HIBE work and no formal security admission: `security_claim=none`, `backend_admitted=false`, `parameters_are_formal=false`, `nist_security_category=null`.
