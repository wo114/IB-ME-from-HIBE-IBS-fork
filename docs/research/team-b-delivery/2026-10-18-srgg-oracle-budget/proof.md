# Table 4 finite H1 rejection accounting

The frozen Jia–Liu–Tang–Wang PDF is `papers/2025_efficient_ibs_jia.pdf`, SHA-256 `258583c5b90255afe91343a282cb62840198b1192b6462dfc9597a24f8c01152`. This is a source-code accounting for the standalone paper implementation, not a theorem claimed by the paper. It uses the original Table 4 `n=512`, `Q=15744063`, and `d=2,3,4`.

`paper_algebra.public_matrix` and `identity_target` call the shared `uniform_values` rejection sampler with `max_trials=256`. For `Q`, each candidate is three bytes. Of the `2^24=16777216` possible values, exactly `Q=15744063` are accepted; the rejected set has `1033153` values. Since `16·1033153 < 2^24`, a single candidate rejects with probability strictly below `1/16` **if its bytes are ideal independent uniform bits**. A coefficient fails all 256 trials with probability exactly `(1033153/16777216)^256 < 2^-1024`. The XOF stream allocates 4096 bytes per coefficient, while the 256 trials can consume at most `3·256=768`; its byte cap does not fire first on this path. Conditioned on success, every residue in `Z_Q` has exactly one accepted three-byte representative and is uniform under this ideal-byte model.

One `public_matrix` address produces `d²n` coefficients. One distinct `identity_target` address produces `dn`; repeated use of an identical framed address reuses the same ideal-oracle value. A union bound on one matrix and one distinct identity address yields strict abort bounds `<2^-1012`, `<2^-1011`, `<2^-1010` for ranks 2, 3, 4. For `u` distinct identity addresses, the exact counted calls are `d²n+u·dn`, and the bound is `(d²n+u·dn)(1033153/16777216)^256`; the program reports a simpler strict power-of-two envelope. These are per-address **hash rejection** bounds only, not Setup or issuance success probabilities and not a service lifetime law.

The code frames all hash inputs with length prefixes. Matrix expansion uses `(domain, "matrix", canonical parameters, 32-byte seed)`, identity target uses `(domain, "identity", canonical public key, identity)`, and message challenge uses `(domain, "message", canonical public key, canonical commitment, message)`. The message challenge takes exactly 512 SHAKE bits directly and does not run the mod-`Q` rejection sampler. The tests exercise the actual shared rejection routine at `Q`, its accepted/rejected boundary and 256-trial abort.

The executable uses concrete SHAKE-256, **not** a literal ideal random oracle. The calculation above is conditional on an ideal XOF model; it gives no statistical distance from concrete SHAKE to a random oracle, no QROM programming argument, and no proof that a fixed 32-byte seed expands to an information-theoretically uniform full matrix.
