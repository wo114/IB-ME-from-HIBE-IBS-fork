## 2. 精确的有限状态参考

固定参数、公钥和根状态。参考状态写作

```text
(root, max_users, committed map C, phase, pending identity/key, storage image).
```

`phase` 包含 idle、reserved、pending-saved、sampled、issued-saved、finished，
以及 blocked。`C` 保存已提交的原密钥，不能在恢复时重抽。首次请求的新身份：

1. 检查输入、目录、pending、规范快照及预期参数/公钥。
2. 命中 C 则返回同一规范密钥；容量满则返回容量错误，两者均不采样。
3. 进入事务，写 pending；第一次且唯一一次调用指定发钥 kernel。
4. kernel 成功时保留完整身份绑定的 key，规范编码/恢复后写 issued。
5. 结束事务后才返回 key。kernel 失败或事务中异常沿与实现相同的故障转移执行。

重开读取可信 storage image，不改变 C，不消费采样 coins。并发按独占锁得到的次序
串行执行；同时到达时谁先取得锁可以是外部调度输入，不能假定某个固定身份先发钥。
本参考允许所有已发钥因全服务阻断而暂时不可读取，不承诺故障后的可用性。

实现还存在两个必须保留的边界：

- `_begin` 在新发钥的 try 块之前。若创建标记前就失败，原 idle 状态可能仍可重试；
  如果标记已出现，后续读取被挡。两种情形均未进行发钥采样，不能误记成“采样失败后重抽”。
- issued 写入及 pending 删除之后、返回之前进程退出，可能留下一个**已提交但调用者
  未收到**的 key。重开可以返回这把原 key；不能在参考中先删掉它再新发另一把。
  若 `_finish` 自身抛异常，则执行补写/阻断路径。没有持久化保证时，不推断硬断电后的状态。

同样，`return key` 真正返回前还要退出 `with self._locked()`。若锁释放/上下文退出
抛异常或此时进程退出，该异常发生于内层 try 之外，不会执行其中的 `_block`；
issued 快照和已删除的 pending 可能保留，而调用者仍未取得响应。参考的 finished
阶段因此还包含锁退出及其故障，恢复时仍复用已提交 key，不把它当作未发钥重抽。

因此“任何错误都永久 blocked”和“只有调用者收到 key 才算 committed”都不是这里
采用的服务语义。该参考逐阶段保留实现的相应结果，不靠成功重试来匹配样本。

## 3. 包装等价引理

**假设 S。** 文件操作、原子替换、进程退出及锁调度满足契约的实际语义，所有参与者
合作；输入验证和编解码保持这里的完整合法状态；算术/库正确。故障及调度由相同的
因果 kernel 产生，依赖共同已观察 API 历史、共同事务阶段和共同存储内容。
若它依赖尚未纳入 kernel 输出的采样内部轨迹或耗时，须先扩充比较的状态及距离，
不能直接用下面的结论。

**引理 1（相同 kernel，零包装距离）。** 从相同完整初态出发，在 S 下给实际服务和
上述参考相同请求、锁/故障 coins、发钥/签名 kernel 及 coins，则每一步的可见轨迹和
已提交 map 逐点相同；故二者 API 轨迹 TV 为零，包含已建模的失败和重开。

证明：按锁内的事务阶段归纳。idle 时相同的严格读取/验证得到相同完整状态。
缓存命中返回同一字节；容量及验证失败走相同分支。新请求经过相同保留标记、pending
写入和一次 kernel。成功/失败输出相同，故后续编码、写入、删除、补写及异常标签相同。
每个阶段的共同故障输入得到同一终态；退出不返回未完成响应。重开是同一 storage
image 的确定解码。已提交但尚未返回的结果在两边保留一致。锁把并发调用化为上述
串行转移；锁未完成前的共同调度也是历史的一部分。归纳即得全轨迹相同。证毕。

这是实现到**带相同故障的状态参考**的条件对应，绝不等于“实际服务没有故障”或
“实际服务到普通无故障 IBS 的完整 Delta0 为零”。既有定向故障/并发测试是上述实现
对应的样例证据；不是对所有文件系统执行的形式化验证。

## 4. 更换发钥/签名 kernel：自适应和历史状态

设实际及参考初始完整状态 law 的 TV 至多 `delta_hist`。这包括 root、公钥、全部历史
key、状态和攻击者已有视图的联合分布。共同支持上的每个可达完整历史 h，要求：

```text
TV(Issue_real(.|h), Issue_ref(.|h)) <= delta_I(h),
TV(SignAttempt_real(.|h), SignAttempt_ref(.|h)) <= delta_S(h).
```

kernel 输出须包含后续包装实际用到的 key/失败类别及持久变化。输出 tail 的边缘界
不足以覆盖额外 raw 范数门、尚未记账的异常或和历史相关的 coins。
现有 latent 双门界可作 `delta_I` 的候选前提；它对本处全部可达 root/h 的统一性仍须
由原证书及其数学条件核对，不由本页凭空授予。

**引理 2（自适应停止和固定缓存）。** 在 S 下，最多 `N_I` 次实际新身份发钥、
最多 `N_A` 次签名尝试，若 `delta_I(h)<=delta_I`、`delta_S(h)<=delta_S`，则

```text
TV(Service_real, FaultAwareReference)
 <= min(1, delta_hist + N_I*delta_I + N_A*delta_S).
```

证明：先最大耦合初态；在仍相同的共同历史上，对本次带完整标签的 Issue 或
SignAttempt kernel 最大耦合。其余共同存储/调度/验证转移按引理 1 使用相同 coins。
首次差异前自适应请求、容量/故障决策及停止事件都相同；每个本轮真的调用相应
kernel 的条件分歧概率由统一界控制。对首次分歧求和，得到上述界；以后如何分叉
不影响上界。若次数不足用零分歧 dummy 步补足，故自适应退出不另付条件化费用。
任何 API 轨迹事件的概率差不超过耦合失败概率。证毕。

缓存命中、重开和已发 key 的确定 round-trip 不计入 `N_I`；同一 key 发生新的 Sign
仍需按实际尝试计入 `N_A`。同身份第一次采样后即使没有成功返回，只要发生了抽取，
该调用已收费。不可把 `N_I` 换成只统计显式 Extract 的次数：Sign 内部首次发钥亦计入。
单次 Sign 的范数重试至多 L 次，因此可保守取 `N_A<=qS*L`，而非只收费 qS 次。

若已有状态按真实服务建立且两游戏从该**相同 law**继续，可取 `delta_hist=0`。
这仅证明该共同初态之后的条件替换，不证明它等于理想 IBS 的历史 law。
若要把此前真实已发钥换成理想钥，必须保留其与先前签名/oracle 视图的联合距离，
不能在恢复后重新声明密钥独立。极端反例：先前公开视图 V=K，真实初态仍存 K；
参考独立重抽 K'（二元均匀）。两边 key 边缘均匀，联合 TV 却为 1/2。

## 5. 普通 IBS 参考额外需要的故障项

再设 `IdealNoFault` 使用相同 reference kernel/初态，但删去某些可见故障/中止。
必须给出一个**未条件化**的共同参考实验，其中被删事件的全局概率至多 `epsilon_F`。
两实验在首次该事件前逐点相同，故

```text
TV(Service_real, IdealNoFault)
 <= min(1, delta_hist + N_I*delta_I + N_A*delta_S + epsilon_F).
```

可以让两个安全游戏保留相同失败接口而避免删除这些故障；此时还需重新核对整个
归约是否回答同一接口，不能暗中引用只接受无故障签名服务的安全定理。
如果尚无共同故障模型/概率，`epsilon_F` 就是未实例化项，不能因测试没崩溃而填零。

一个二元例子说明为什么不能“只看正常运行”免费完成这一步。真实 key K 均匀于
{0,1}，存储仅在 K=1 时失败，成功时返回 K；故失败率 1/2，完整 law 是
`{return 0:1/2, fault:1/2}`。无故障理想 law 为 `{return 0:1/2, return 1:1/2}`，
TV=1/2；真实成功条件 law 则 K 恒零，与理想均匀 law 仍差 1/2。
即使故障独立，若它以概率 f 返回一个理想游戏不可能出现的公开错误，TV 也至少 f。

这里的“未条件化”不禁止环境根据已公开 API 历史选择故障；它禁止删除坏轨迹后
再把剩余实验中的 kernel 称作原来的无条件 kernel。

## 6. 与当前证据及剩余目标的关系
