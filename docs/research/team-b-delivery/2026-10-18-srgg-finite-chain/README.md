# SRGG source-Schur finite-chain audit (WIP)

This package uses the original paper's Table 4 inputs (`n=512`, `p=16383`, `b=31`, `w=2`, `q=961`, `Q=15744063`, `d=2/3/4`) and preserves both explicit interpretations of its rounded Gaussian widths. The frozen Jia–Liu–Tang–Wang PDF is [`papers/2025_efficient_ibs_jia.pdf`](../../../../papers/2025_efficient_ibs_jia.pdf), SHA-256 `258583c5b90255afe91343a282cb62840198b1192b6462dfc9597a24f8c01152`. This is standalone IBS work; no HIBE is selected or integrated.

For six replayed successful fixed Setup roots and one issued Alice key per root, [`finite-fixed-root.json`](finite-fixed-root.json) bounds the actual source-Schur sampler's integer output, with abort, against the **mathematical Algorithms 3–4 chain using the same current rational parameter interpretation**. It covers all 512-bit midpoint tickets, 768-bit MPFR arithmetic under its stated correct-rounding/no-fault premise, the active 256-bit dyadic centers, scalar rejection and aggregate byte caps, and the exceptional rational-input bit gate. The proof and exact scope are in [`proof.md`](proof.md).

| Table 4 row | Finite → mathematical Algorithms 3–4, master / sign | Finite → ideal joint integer Gaussian, master / sign |
|---|---|---|
| PARAM-I | `≤2^-72 / ≤2^-71` under both interpretations | Standard-deviation interpretation `≤2^-26 / ≤2^-25`; literal-density interpretation `<0.6781 / <0.8964` |
| PARAM-II | `≤2^-72 / ≤2^-71` under both interpretations | Standard-deviation interpretation `≤2^-25 / ≤2^-24`; literal-density interpretation `<0.8174 / <0.9667` |
| PARAM-III | `≤2^-71 / ≤2^-70` under both interpretations | Standard-deviation interpretation `≤2^-25 / ≤2^-24`; literal-density interpretation `<0.8964 / <0.9893` |

The second column of bounds is distinct from the first: [`joint-fixed-root.json`](joint-fixed-root.json) adds a mathematical convolution comparison from exact continuous-plus-discrete Algorithm 4 leaves to ideal discrete Schur leaves, then the separately certified ideal sequential-vs-joint Schur normalizer bias. At `n=512,r²=1.3456`, the literal-density branch fails the original all-center theta sufficient condition. The first allowed alternative, a coordinate-product normalizer bound, gives the trivial **chain bound exactly 1**; its reproducible failure is in [`literal-product-fallback.json`](literal-product-fallback.json). The second and final alternative bounds the Fourier second moment under the actual continuous Gaussian at fixed roots whose Schur pivot floor was audited as 64. Its 4–16-leaf bounds are strictly below 1 but about `0.678–0.989`, much too weak for security. The proof and exact rational bounds are in [`proof.md`](proof.md) and the joint receipt. Even the standard-deviation joint bounds (`2^-24` to `2^-26`) are too large to establish formal security after many adaptive calls.

Each fixture performs one Setup and one five-byte identity extraction to obtain the fixed geometries; this audit does not sign a message or rerun the earlier 32-byte lifecycle tests. The deterministic test seed enables replay and does not establish the proof's independent-uniform-byte premise. The run used WSL2, Sage 10.9, Python 3.13.15, an Intel Core Ultra 7 255HX and about 31.4 GiB RAM. The original IBS object flow uses ROM, but no security game was rerun here. These are published Table 4 inputs, not project-admitted formal parameters.

The theorem's target for the standard-deviation branch uses this repository's 512-bit rational approximation to the `π` scaling, not an assertion about an unpublished exact author value. Paper ambiguities in the lower-block width, Algorithm 4's `d/f`, the signing `ζ` factor, `q/Q/2Q` theorem mapping, and native strong game remain as documented in the [source review](../2026-10-18-srgg-closure-followup/source-and-security-review.md). Accepted-Setup-root distribution, full issuance/signature/fault history, structural attack costs, and author C/ANS/1000-run performance remain open. Functional tests and these fixed-root bounds are not a security proof or a NIST-category admission.

Exact validation is in [`validation.json`](validation.json), with byte hashes in [`MANIFEST.json`](MANIFEST.json). Security markers remain `security_claim=none`, `backend_admitted=false`, `parameters_are_formal=false`, and `nist_security_category=null`.
