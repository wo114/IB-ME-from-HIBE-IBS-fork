# SRGG 后续路线比较：先列候选，再核证据

日期：2026-10-16。目标：在 HIBE 尚未确定时，选择能有效推进 SRGG 分布对应、strong 安全前提和大维度真实采样的路线。本文只提出并比较研究／实施路线，不报告已完成安全归约，不声称创新。

版本说明：下列“第一轮／第二阶段／分机制比较”保留本日较早时的候选和证据快照，包含当时尚未实现的预测；**当前实证与推荐以后文“同日后续实证”及末尾工作次序为准**。不覆盖旧记录来伪造预先已知结果。

## 范围、偏差和预先规定的比较标准

研究问题是：**怎样最少返工地得到有可核验分布与安全前提、并能真实运行的独立 SRGG IBS，或者及时识别这一路线不适合作为最终代表？** 当前主实现、真实小维生命周期和已有负控予以保留；HIBE 选择、共享 CLI、最终三组评选及正式安全等级不在本文件的决策范围。

本轮采用 `scientific-brainstorming` 工作流。记录者是参与过 fiber／HNF 分析的同一 AI，因此有“继续已有数学工作”和“沉没成本”的锚定风险；下面的独立候选只表示未先读取其他 agent 本轮路线建议，不表示未受此前工作影响。没有人类专家或独立外部评审参加本次比较。候选来源均为 AI-assisted 研究建议；有限本地核查不证明新颖性。

评价方向先于证据筛选确定，不给伪精确总分：

| 标准 | 优先方向与需要的证据 |
|---|---|
| 正确性保持 | 精确列出方程、支持、密度、identity/message/context 绑定的保持或改变；一般证明优于仅功能样例 |
| 安全归约保持 | 明确普通／strong EUF、ROM/QROM、查询与中止条件；不以“接口一样”或改范数门代替归约 |
| 参数闭合 | 同时考虑 sampling smoothing、噪声／范数、q/Q 对应、攻击成本；新宽度必须有实际可接受失败率和成本依据 |
| 可测收益 | 以真实发钥／签名及恢复的耗时、内存、尺寸和证书误差衡量；工具数量和只做 matvec 不算方案可运行 |
| 工程成本与可回退 | 能否复用当前对象／服务／方程，是否需要新陷门、密钥和 wire；优先可独立实施且可回退的改动 |
| 失败时信息价值 | 若路线失败，能否留下明确反例、条件不满足证书或可复用基线，而非继续无界扩参 |

## 第一轮独立候选（证据复核前冻结）

| ID | 机制和预期 | 关键假设／可证伪点 |
|---|---|---|
| R1 | 保持当前 approximate gadget／HNF 与签名方程，完成联合 Gaussian→并集 fiber→exact PSF 的桥；同时补源 strong 游戏对应，再优化同一采样器 | 现有分布能够在实用宽度下获得小总误差；strong 目标有可成立的原语依据，或者可单独补归约 |
| R2 | 将近似 gadget 发钥替换成有成熟分布定理的 exact-preimage trapdoor sampler，重新对齐 PSF 与压缩对象 | 需要可达整个模 Q image 的短陷门；当前 p 倍 gadget 不能直接被重命名为满射 exact sampler；改变后仍需签名安全对应 |
| R3 | 先核基础 EUF IBS，再加有明确归约的强不可伪造编译层，使 strong 障碍成为独立组件义务 | 基础 EUF 分布链先成立；编译器与所选一次签名必须确实覆盖 strong 情形，尺寸／模型可以接受 |
| R4 | 保留 SRGG 为真实研究基线和负控，不把它强行列入最终三组；优先比较其它已交付 IBS | 其它候选有独立的适配和安全证据；不是“换个算法名称即可安全”，最终代表选择由统筹／用户决定 |
| R5 | 暂不改变原语语义，使用 negacyclic 频域／块结构实现同一连续 Gaussian 与整数舍入，替代大系数矩阵稠密 LDL | 精确代数、实空间 Gaussian 协方差和有限数值误差可对应；仅加 FFT matvec 不足以实现 sampler |

R5 是可与 R1 或 R3 组合的工程机制，不能单独解决 strong 或 PSF 证明。R2 与 R1 改变的是发钥机制，R3 改变的是强安全获得方式，R4 改变的是项目资源分配；不把它们压成一个“参数更大”的选择。

## 证据后的第二轮候选

新增 **R6：先用可证明的固定公开谱界收紧宽度，再实现结构化 sampler**。动机来自 E5、E7、E10，而不是先假定必须整体乘某个 k。

具体设想是利用 CBD1 多项式矩阵在 negacyclic 根上的块谱表示，以及浓缩／联合界，推导含明确失败率的公开 `||T||²` 上界；再检查其是否同时改善 C、签名宽度、γ、Q 和最终成本。当前最坏支持 Frobenius 界仍保留为无需概率条件的基线。该候选需要新的数学推导，不在本文件声称其更优常数或大参数已经取得。

**可证伪点：** 若达到目标总预算所需的谱界仍接近旧最坏界，或加入失败／conditioning 后的归约与实现复杂度超过降低宽度的收益，就保留原界。不能用有限样本“从未超界”取代尾概率证明。尤其不能简单把 per-key 实测范数发布成参数：参数依赖秘密见证是否泄露信息、是否改变 setup 分布，均需单独处理。

## 分机制比较

| 路线 | 正确性／归约保持 | 参数与可测收益 | 工程成本与不应掩盖的失败条件 | 本轮建议 |
|---|---|---|---|---|
| R1：保持原语语义，补分布与 strong 条件 | 方程和对象可保持；分布桥仍须包含 approx→exact、HNF、范数门，签名 ζ 离散卷积另算。strong 仍须真实矩阵分布的 CUR/UF-NMA、HVZK/entropy 与整个 IBS 游戏 | 最直接利用 E4；n8 可先算完整账本；旧 n512 正定点不够。收益以能够识别的完整 reference 和总误差衡量 | 数学工作可分块，但“不停再列一项缺口／再写一个工具”不算完成。若 strong 前提与真实矩阵分布无法对应，须给明确停止点 | **保持为语义基线并先完成低成本判别，不把重型 n512 实现放在它前面** |
| R2：改成 exact-preimage trapdoor sampler | 能从机制上简化近似误差混合；但当前 `p*g` image 仅为 p 倍子群，不能把已有 T 直接当 full-Q 满射陷门。须新 trapdoor/PSF 对应，可能改变公钥、发钥与 wire；签名 strong 障碍仍在 | 可借成熟 exact-preimage 定理减少自创桥接；代价可能是维度、密钥和签名增大。实际收益未知，必须与保留 R1 的总成本比较 | 需与 A 的 MP12／格工具负责人逐文件协调；不复制其工作、不以替换后仍“同名 SRGG”掩盖算法改变 | **储备备选。仅在原语语义改变被接受且 R1 明确受阻时提升，不是下一步默认重写** |
| R3：普通 EUF IBS + strong 编译层 | 基础 EUF 不由编译层修复；需要明确 multi-query、identity/context 和一次密钥模型。强 OTS 可覆盖旧消息新签名分支，但不能仅凭普通 OTS 安全就宣称 sEUF | 有机会把 source strong 的两层困难改为已核验基础 EUF + 组合归约；增加认证公钥、证书和签名字段，容量/时间成本取决于选择 | 必须先查当前 BYTEAUTH 是否已满足实际组合目标。若组合无需独立 sEUF，再在每个 IBS 加一层可能重复付费；QROM 保留性仍要证明 | **当“独立 SRGG 本身必须 strong”且原生路线不合算时再选；不立即实现** |
| R4：研究基线保留，最终代表使用其它候选 | 保留所有负控和研究数据；其它 IBS 仍要通过各自安全条件，现有 ML-DSA/Falcon 认证转换也不是自动 strong／QROM 准入 | 避免将全部项目资源投入来源有冲突的单一候选；收益由最终同目标公平比较确认 | 是最终代表／资源取舍，不是本轮 AI 可自行取消用户 SRGG 任务的理由 | **作为有价值的退出选项，最终选择交统筹／用户，不拿它代替当前授权工作** |
| R5：频域／结构块 sampler | 理论上可保持同一 Gaussian 目标和整数舍入。须证明单位变换、复共轭配对、密度 shape 与物理协方差、Schur／中心和有限数值误差的保持 | 从 `nL × nL` 系数稠密对象转向 n 个小模块频域块，模型存储可从 `O(n²L²)` 到 `O(nL²)`；块分解模型从 `O(n³L³)` 到 `O(nL³)`，另计变换。是模型预测，未测提速 | 要完成真实 draw，不只是乘法。现有 LDL 专属误差证书不能自动移植给 FFT；有限票据先在连续域 TV=1 的问题仍须按最终离散输出处理 | **R1/R6 的首选工程路径，先做能推翻自己的小参数端到端 sampler 原型** |
| R6：收紧公开谱界，再定参数 | 不改关系式；若新 setup 按谱事件 abort/reject，分布变化与概率须计账。若采用无拒绝的高概率分析，异常事件也须进入 correctness/security 损失 | 可同时降低 master/signature widths 和压力；只有真实总预算改善才有收益。不能先宣称一个未推导的 n 倍优化 | 需要概率谱界与精确／区间 witness 核验机制；优先固定公开参数，不发布 per-key 秘密 norm | **与 R1 的分布桥并行先做数学判别；有明确收益后再替代最坏界，而非先扩 w 和 k** |

### strong 障碍怎样改变优先级

源参数的 CUR 对已经使“直接套 KLS 便能 strong”的路线失去资格；当前 Q gate 只是排除已知 pair。也不能把普通新消息游戏改名为 strong 赢法后继续用旧模拟器。因此，**在 strong 仍作为独立原语目标时，必须先做一份可判定的前提映射／反证，而不是先优化源参数的签名速度**。若关键矩阵分布无法对接已估计的 MSIS 或其它明确假设，应停止向原生 strong 路线追加安全声明，比较 R3。

但现有 Wang／BYTEAUTH 组合职责与独立 sEUF 不同。BYTEAUTH 对更换外层认证公钥的分支绑定 IBS 新输入，对同一公钥改字节的分支使用强一次性签名条件。**普通 EUF IBS 是否足以满足当前组合模型，应由统筹按现有契约核定；不能无依据地把源 strong 冲突升级为整个 SRGG 研究暂停条件。** 即便只要求普通 EUF，分布、真实假设、固定发钥和中止仍必须闭合。

R3 的机制示例（仅研究提案）：每次 IBS 签名生成一次密钥 `(vk_o,sk_o)`，先对规范 `LP(m)||LP(vk_o)` 作基础 IBS 签名 τ，再由强一次性签名签 `LP(m)||LP(τ)`，输出 `(vk_o,τ,σ_o)`。未用过的 `(id,m,vk_o)` 分支应归入基础 EUF；已使用分支中的新 τ 或新一次签名字节应归入强 OTS。还需形式化 oracle、碰撞、编码、身份上下文及 multi-user／QROM 损失。这个例子说明机制上的可能性，没有选择、实现或准入某个具体编译器。现有 BYTEAUTH 是密文层机制，不能直接当成独立 IBS strong 的定理引用。

## 对首选路线的反向质询

| 质询 | 当前回应和剩余不确定性 |
|---|---|
| 继续 R1 是否只是因为已经投入了 HNF／fiber 工作？ | 有该锚定风险。先以能否得到完整 reference 和有限总预算作为停止判据；R2/R3/R4 保留。fiber 小误差本身不作为偏好 R1 的充分理由 |
| C 的旧下界失败，是否只能把 master width 翻倍／扩大 w？ | 不是。可以比较更紧的公开谱界、适度形状 slack、采样结构和完整 PSF 误差；哪个有效由证书和实际成本决定。下界失败也可能只是保守性，不能宣称实际分布失败 |
| 有 FFT 就能获得大参数性能吗？ | 不能。误差、共轭、整数舍入、范数失败和真实 lifecycle 都要通过；若必须回到巨大有理系数或误差随条件数失控，则 R5 预期收益被推翻 |
| 换成 exact sampler 是否立刻得到安全？ | 不能。公钥／trapdoor 分布、SIG strong、固定发钥与 query 模型未由 exact sampling 解决；R2 是新机制成本而非清除所有未知 |
| 加编译层是否能够绕过当前 source 反例？ | 它有机会阻止同消息的新外层签名，但基础 EUF、强 OTS 和组合模型必须先成立；若只是重新编码而无强安全组件，反例并未消失 |
| 改用其它候选是否自动优于 SRGG？ | 不能。尚无同安全目标、合法参数和完整组合成本对照，故不把 R4 表述为已证明的最佳方案 |

这是记录者对自身方案的 adversarial pass，没有伪称独立专家已复核。独立审阅应专门挑战 R1 语义保持、R3 strong 分支和 R5 实空间分布对应，而不是重复跑相同样例。

## 可以直接实施的下一批工作

当前推荐更新为 **保留既有原语方程与目标语义 + R6 已证明的公开支持谱界 + R7 已验证的结构采样／独立执行路线**，同时保留 R1 的分布和安全义务。早期默认优先实现 R5 的建议由当前证据更新；FFT 继续作为候选，不能把未测比较写成胜负。

1. **先固定两个实验目标。** 普通 EUF 用当前 fresh-message 定义；独立 strong 另用“返回过的确切三元组”赢法。列清各自需要的原文定理／实际分布、ROM/QROM、固定发钥和中止条件。保留当前用户 strong 研究目标，不替其降级；这份映射不需要另问许可。
2. **集成已证明的 mixed-domain 与 oracle 账本。** 从有限 sampler、理想 perturbation／gadget、raw union 到混合域条件 law、相同 HNF/norm gate 和固定服务逐项对齐。不得继续加不匹配零中心参考的位移罚项，也不得遗漏逐目标 norm／abort、短域、aliases 熵和多查询条件；保留 n8 的公开伪造负控。
3. **采用 R6 无 conditioning 的确定性公开界。** 将 ζ、γ、Q、TV、setup/extract/sign 失败、资源门及成本一并传播。现有支持界已足以推进，不再以尚未需要的概率谱筛选或擅自扩大 width 为下一步默认动作。后续参数与攻击成本仍单独核定，不以数学／工程证书通过换取正式安全等级。
4. **以 R7 完整执行版本继续可复现验收。** 保留其独立命名空间及与旧顺序 finite law 的区别，冻结实际依赖和 JSON；对真实发钥、恢复后签名及失败路径做必要回归。若要作速度／内存比较，另预定同参数、同数值误差、重复次数、失败和中位数／IQR；一次 n512 成功不是基准排名或可靠率。
5. **保留 native strong，准确限定新增归约工作。** 按 theorem-obligations 的来源义务继续判别：mixed keygen 下 HVZK/commitment entropy、真实分布的 CUR/UF-NMA、目标身份 SIG 签名模拟、跨身份新鲜性和 QROM 损失。数学／测试已完成部分正常交付；原文未给的新安全归约、是否采用可标识变体及最终代表价值选择留待用户／统筹确认，不把 compiler 当作 ordinary EUF 的替代证明。

以上均在既有独立原语工作范围内，可直接推进。新算法／公共 wire、共享组合协议、跨组文件的改变先按仓库分工协调，不以 routine 实现问题反复询问用户。

## 真正需要用户／统筹决定的分歧

目前不能从数学或功能测试唯一决定以下价值取舍，因此不替用户假定：

- **已确认的后续方向。** 用户在本批发布前明确选择“继续专攻 SRGG 的安全归约，保留原生 strong 目标”。因此下一阶段继续研究 mixed key-generation 下的底层强安全和修正后的 IBS/QROM 归约；工程采样验收不代表这部分已经完成。不删除已知反例，不将 ordinary EUF 改写成 strong。
- **是否允许以明确标识的“SRGG 变体／派生实现”替换原发钥或增加编译层**，接受密钥／签名／wire／模型的变化，还是要求严格复现冻结论文算法。R2/R3 是否可成为主线取决于这点。
- **最终代表是否必须包含 SRGG**。如果其强安全或资源条件无法以可接受成本闭合，R4 保留其研究成果、让更合适的候选进入三组代表，属于项目选择；当前证据不足以自行宣告哪个替代方案最优。

这些分歧不阻塞上面已授权且可独立实施的证明、谱界比较和结构化 sampler 工作。本文没有要求立即停工等答复，没有改变任何生产代码／共享接口／正式参数，也没有给出新的安全准入声明。
