## 4. 已确认的组合流程

设发送者身份为 `sender_id`，目标接收者为 `receiver_id`，消息为 `message`。

以下是根据公开组合说明整理的算法摘要，不是对目标论文全部算法的逐字转录。

### Setup

分别运行 IBE.Setup 和 IBS.Setup。公共参数组合为两个原语的公钥；主私钥组合为两个原语的主私钥。两套参数分别保存。

### SKeyGen

用 IBS.KeyGen 为发送者身份提取签名密钥。同一用户获得的密钥必须可持久保存并用于多条消息，不能每次 Encrypt 隐式重新发钥。

### RKeyGen

用 IBE.KeyGen 为接收者身份提取解密密钥。本路线没有 HIBE.Derive。

### Enc

1. 规范编码 `(sender_id, receiver_id, message)`。
2. 用发送者 IBS 密钥签名该三元组。
3. 规范编码 `(signature, message)` 为载荷。
4. 用目标接收者身份调用 IBE.Enc 加密载荷。

### Dec

1. 用接收者 IBE 密钥解密载荷。
2. 严格解析签名与消息，拒绝截断、追加、重复字段及非规范表示。
3. 以期望发送者身份 `expected_sender_id` 验证签名；验签消息绑定该身份、接收密钥身份和恢复出的消息。
4. 成功返回完整消息；解密、解析或验签的数据失败统一返回 BOTTOM。

只有规范 API 的通过/失败流程已确认。持有目标 IBE 私钥的用户可以绕过组合 API 调用底层解密，因此不能把 API 的发送者不匹配拒绝理解为恶意接收者的增强隐私。

## 5. 拟定模块与接口

独立实验根目录拟为 `experiments/ibe_ibs_yu2026/`；确切后端文件在全文核对后冻结。

| 模块 | 责任 |
|---|---|
| protocol.py | 五个组合算法，只调用原语接口 |
| encoding.py | 独立域标签、长度前缀、三元组和载荷规范编码 |
| types.py | 公共参数、主私钥、发送者密钥、接收者密钥及版本信息 |
| ibe_api.py | setup/keygen/encrypt/decrypt 与对象加载契约 |
| ibs_api.py | setup/keygen/sign/verify 与对象加载契约 |
| 后端模块 | 依据完整论文分别实现 Boyen–Li IBE 和 Yu–Liu–Li IBS |
| tests/ | 组合契约、原语方程、序列化、固定密钥复用及负面对照 |
| demo.py | Alice→Bob，成功、双方身份不匹配和畸形密文演示 |
| benchmark.py | 可复现尺寸、耗时、参数、环境及失败率记录 |

首个接口原型使用 Python，与现有项目接口和规范编码经验保持一致。精确格采样若依赖 Sage，在用户项目约定的 WSL `~/miniconda3/envs/sage` 中运行。环境可用性尚未验证。

不将普通签名包装成 IBS、不把 SHAKE 哈希直接当作论文标准模型 PRF、不用均匀或四舍五入连续高斯冒充证明所需的离散高斯。

## 6. 验收与测试

- 匹配身份恢复空消息、二进制消息及容量边界消息。
- 接收者不匹配、发送者不匹配、双方不匹配时，规范 API 返回 BOTTOM。
- 同一发送者持久密钥签多条消息；跨进程保存/加载保持密钥及规定状态语义。
- 验签拒绝身份替换、接收者替换、消息替换和无钥伪造。
- 编码严格拒绝截断、追加和重复字段；公开加载不执行 pickle 或任意代码。
- 原语级核对矩阵关系、维度、整数范数、噪声和解密界。
- 固定随机流只用于测试；正式随机入口明确区分。
- 保留公开线性求解/格约化攻击对照，不能仅测试随机签名伪造。
- 外层密文篡改拒绝作为单独待证明性质，不默认从 IBS 自动继承。
- 先测真实后端，再给出与 HIBE + IBS 的公平比较；测试替身的速度不纳入密码性能数据。
