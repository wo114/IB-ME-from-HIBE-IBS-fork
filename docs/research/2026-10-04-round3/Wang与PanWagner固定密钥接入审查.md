# 第三轮：Wang 基本 IBS 与 Pan–Wagner 固定密钥接入审查

日期：2026-10-04。任务边界：审查同一个发送者密钥被保存并用于多次签名时的算法、查询转录与归约。本轮不改通用 IB-ME 构造，不开发 Boyen–Li 增强隐私，不修改密码后端或教学参数。

## 1 结论及准入状态

**Wang 基本 IBS + Pan–Wagner ROM 转换作为优先推进的数学参考候选；固定用户密钥版本仍需补充证明，尚未获准作为安全完整后端接入。** 本轮已写出允许后续腐化查询的条件归约草案及其损失，不再把“加两个盐并缓存密钥”视为自适应安全已经成立。

## 3 完整候选算法及字段

### 3.1 四个哈希应分清

用 `J_id`、`J_msg` 表示 PW 外层随机预言机，避免与 Wang 内层 `H_id`、`H_msg` 同名。内部身份空间取可均匀采样的有限集合 I，消息空间取集合 N；用比特串实例化时，分别记长度为 `b_id`、`b_msg`。二者均不同于原始身份和用户消息的字节长度。

| 哈希 | 输入 | 输出 | 用途 |
|---|---|---|---|
| `J_id` | 长度前缀编码的原始身份 `id`、身份盐 `r` | `x ∈ I` | PW 身份转换 |
| `J_msg` | 长度前缀编码的待签字节串 `M`、消息盐 `s` | `y ∈ N` | PW 消息转换 |
| `H_id` | 公钥矩阵 `A` 的规范编码、`x` | 均匀矩阵 `Z_q^(n×w)` | Wang 身份矩阵 |
| `H_msg` | 公钥矩阵 `A` 的规范编码、`x`、`y` | 均匀向量 `Z_q^n` | Wang 签名右端 |

建议四个独立域标签分别为 `IBME-IBS-PW-ID-v1`、`IBME-IBS-PW-MSG-v1`、`IBME-IBS-WANG-H1-v1`、`IBME-IBS-WANG-H2-v1`。这是待实现的编码规范建议，尚未修改现有 Core。标签与长度前缀是对预言机输入的单射重编码，不改变四个函数的职责。不能把 `x` 随意加入 `J_msg` 后继续沿用原转换的逐项映射。

PW 外层消息哈希不含身份；Wang 内层消息哈希含内部身份 `x`。同一个 `(M,s)` 可以被不同身份共用，内层签名方程仍分别绑定 `x`。四个域也要与 HIBE 哈希分开。以 SHAKE 实现均匀模 q 输出时需要无偏拒绝采样或明确的偏差界；SHAKE 实例化并不等于真实随机预言机。

### 3.2 Wang 基本算法

令 `k = ceil(log2(q))`、`w = n*k`、`d = m_matrix+w`。以下 `m_matrix` 对应原文矩阵列数 m。

1. Setup：执行 `TrapGen(n,m_matrix,q,s0)`，得到 `A ∈ Z_q^(n×m_matrix)` 和秘密 G-trapdoor `T_A`。按 MP12 维度，`T_A` 是 `(m_matrix-w)×w` 的短整数矩阵，不是一个 `m_matrix×m_matrix` 完整格基。
2. KeyExt'：取 `B_x = H_id(A,x)`，形成 `F_x = [A | B_x] ∈ Z_q^(n×d)`；执行 `DelTrap(F_x,T_A,s_del)` 得到短整数陷门 `T_x ∈ Z^(m_matrix×w)`。
3. Sign'：取 `h = H_msg(A,x,y)`，执行 `z ← SamplePre(F_x,T_x,h,s_sig)`。`z ∈ Z^d`，应满足 `F_x*z = h mod q`。
4. Verify'：检查维度、`z != 0`、上述模方程及 `||z||_2 <= B_verify`，其中原文使用 `B_verify = s_sig*sqrt(d)`。

`T_x` 可与原文的正号关系 `B_x = A*R_x + G` 对照；MP12 的 `[A|B_x] [-R_x; I] = G` 用负号陷门。适配层必须固定一个约定，不得把正号 R 当作 MP12 的同号 trapdoor 使用。

**真实算法的 B_x 是公开均匀矩阵，陷门由主秘密委派。** `A*R_x+G` 或 `A*R_x` 是证明模拟中的可编程关系，不能公开生成一个人人可重算的短 R 后声称它是发送者私钥。旧原型的这类风险没有在本轮修复。

范数检查用有符号整数向量；不能先取 `[0,q)` 代表再计算范数。原文尺寸表按模 q 元素描述密钥和签名，本项目要保留短整数及真实范数，不能直接据此填写序列化尺寸。应使用带符号、定维、规范的整数编码，拒绝非规范编码、截断、追加和重复字段；与现有签名容器的适配需在实现前冻结。

### 3.3 PW 外层及持久化状态

| 操作 | 必须完成的内容 |
|---|---|
| 发一份密钥 | `r ← {0,1}^ell`；`x = J_id(id,r)`；`sk' = KeyExt'(msk,x)`；返回保存原始身份、r、x、T_x、公钥上下文或可校验的公钥引用、参数指纹及版本的密钥对象 |
| 使用既有密钥签名 | 保留 r、x、T_x；每次新取 `s ← {0,1}^ell`；`y = J_msg(M,s)`；`z = Sign'(sk',y)`；返回完整签名 `(r,s,z)` |
| 验签 | 从签名读取 r、s；从外部期望身份重算 x，从完整待签字节串重算 y，再执行 Verify' |
| 保存及加载密钥 | 恢复相同 r、x、T_x 和上下文，检查身份/参数/版本关联；不能恢复时重新随机取 r 然后沿用旧 T_x |
| 重复签同一个 M | r 相同；s 和 SamplePre 随机性分别重新取得；偶发相同 s 属于概率预算，不能假定永不碰撞 |

转换增加两个盐，共 `2*ell` 比特，实际字节数另加容器及版本字段。`ell`、内部哈希输出长度和签名整数宽度都还未选成正式参数。本轮没有把某个常见盐长度直接写成“128 位安全”。

现有接口是 `sign(sk,M)`，没有单独传入 pk；因此密钥对象或后端的受检上下文必须提供 A 和签名参数，仅存一个公钥摘要不能计算内层哈希。公钥包含 A、方案/编码版本及独立参数配置，主秘密包含 T_A 与相同上下文；签名含 r、s、定维 z 及格式版本，x、y 由验签者重算，T_x 永不进入签名。所有上下文关联都需加载时校验，不能靠未受检的全局变量绑定。

IB-ME 的 `M` 继续是现有 `encode_message(rcv,message)`；HIBE 顺序仍为 `(rcv,phi)`，载荷为完整签名与消息。盐属于加密载荷里的签名字段，不应新设含身份的公开密文头部。原语新增格式必须走公共接口，不能让协议层读取 T_x 或内部矩阵。

## 4 查询模型为何不能混用

PW Figure 1 的 Sig(id,M) 明确执行 `KeyExt(msk,id)` 后才 Sign。因此同一个外部身份的两次签名通常含两个独立 r。Figure 5 的算法本身却完全允许对保存的 `(r,sk')` 重复调用 Sig。这是**算法支持的使用方式与定理中查询实验的区别**，不是本轮发现了真实伪造攻击。

| 查询顺序 | 论文 Figure 1 / Theorem 2 | 本轮拟采用的缓存实验 |
|---|---|---|
| `Sig(A,M1), Sig(A,M2)` | 两次发钥；内部身份通常不同 | 一次发钥；r、内部身份、陷门全部复用 |
| `Sig(A,M), Sig(A,M)` | 两份新发密钥、新消息盐 | 同一密钥；新消息盐和新采样随机性 |
| `Sig(B,M), Key(B)` | Key 查询再次 KeyExt | 返回 B 签名时已有的同一份密钥 |
| `Key(B), Key(B)` | 可返回两次随机发钥结果 | 同一生命周期内返回已有密钥 |
| 密钥保存后再次签名 | 不由单次 oracle 转录自动说明 | 与未重启时同一份密钥签名的分布一致 |

拟采用的缓存实验中，`GetKey(id)` 在首次 Key/Sig 查询时只生成一次密钥；Key 返回已有密钥并记录腐化，Sig 用已有密钥并记录 `(id,M)`。获胜条件是目标身份未被 Key 查询、原始 `(id*,M*)` 从未被 Sig 查询且签名有效。允许腐化其他身份，允许其在签名后才被腐化。该实验只覆盖**单实例、单身份单密钥生命周期**。

当前 `IBSBackend` 并未规定重复 `key_extract` 自动返回同一份密钥。因此缓存发钥策略仍是待冻结的服务层规范，不能用本研究悄悄改变接口实现。重新导出已有密钥、随机发一份新密钥、在新主公钥下轮换密钥，必须分别记录。多份同身份密钥同时使用及跨实例攻击仍需另行建模。

## 5 旧证明具体在哪一步失效

PW Theorem 2 的 G1 在新 Key/Sig 查询使用的 `J_id(id,r)` 或 `J_msg(M,s)` 已定义时中止。原实验依赖刚生成的 r、s，把中止概率压到 `(Q_C+2Q_S)*Q_H/2^ell`。

固定密钥第二次签名会有意命中已有 `J_id(id,r)`，若照搬 G1，中止概率就是 **1**。即使忽略这次中止，原归约为每次签名预先准备独立 `(x_i,y_i)`，仍不能把已经固定的 `J_id(id,r)` 重编程成下一个 `x_i`。合理修订必须为同一用户保持 x 不变，改造预承诺列表和模拟器。

另一个必要问题是后续腐化：若给所有用户预留签名、但没有请求它们的基础密钥，就无法回答“先 Sig(B)，后 Key(B)”。本轮草案让归约预先请求除猜测目标以外的所有密钥；目标因获胜条件不允许腐化，正确猜测的成功路径不会要求归约交出它的密钥。

不能只说“每份签名的边缘分布看起来一样”。r 是签名里的可见字段：同一身份两次查询，在缓存实验中 r 相等概率为 1，在重发钥实验中为 `2^-ell`。这些联合转录的总变差距离为 `1-2^-ell`，它说明两个实验不能直接等同，不说明哪一个实验存在伪造。

## 6 可继续推进的条件归约

完整草案见 [固定密钥转换条件归约草案](固定密钥转换条件归约草案.md)。概要如下：

1. 将成功伪造分为目标从未请求签名的 F0，以及目标曾请求签名的 F1。
2. F0 归约 B0 在 Setup 前请求所有预留身份槽位的基础密钥，用它们模拟 Key 和缓存 Sign。最终未发钥、未签名目标的内部身份应落在这些槽位之外，需排除哈希碰撞。
3. F1 归约 B1 在 Setup 前均匀猜一个目标槽位 g，为其他槽位请求基础密钥，只为 g 预先请求至多 Q_S 份不同内部消息的签名。在线对 g 保持身份哈希不变，只编程新消息盐对应的哈希。
4. 其他用户的签名与后续 Key 查询都用同一份已知密钥。猜错并发生目标槽位腐化时中止；猜中最终目标的成功路径不会中止。
5. 未用完的预承诺签名也属于基础实验的已签列表；不能只排除在线已经返回的消息。最终伪造使用不同 r 时也必须验算，不能强行要求其 r 等于合法签名的 r。

令 `K = max(1,Q_C+Q_S)`，草案的外层损失最多约 `K+1`，**不再沿用 PW 紧归约的损失**。这不是另一个 IB-ME 通用构造，修改的是底层转换在实际发钥策略下的证明。

关键额外条件是 SamplePre 的**统一、条件化**分布界：在全部合格 T_x、目标 h、已见查询历史下，使用新随机性得到的签名都接近同一个不依赖陷门的陪集离散高斯。Wang Lemma 2.6 给出方向；有限 s_sig、统一陷门谱范数界、坏密钥概率和采样误差还必须具体化。逐次混合的误差随 Q_S 增加，不能由一次采样测试消掉。

## 8 本轮精确检查及其解释

[核验脚本](../../../experiments/research/fixed_key_transform_audit.py)用四元素盐空间做完全枚举；没有随机抽样或真实签名。结果见 [JSON](固定密钥转换精确核验结果.json)。

| 检查 | 精确结果 / 含义 |
|---|---|
| 同一身份签两次，可见 r 的联合分布 | 缓存全相等概率 1；重发钥为 1/4；总变差 3/4 |
| 同一身份签三次 | 重发钥全相等为 1/16；总变差 15/16 |
| 不同身份各签一次 | 两种盐分布相同，控制组差距 0 |
| `Sig(A), Sig(B), Sig(A), Key(B)` | 猜中 A 时两次 A 使用 x-1；B 可返回其既有密钥 |
| 同一消息重复签名 | 身份盐保持；消息盐与内部消息槽位变化；旧原始消息不构成新的 UF-CMA 伪造 |
| 未用预签名槽位 | 仍被判为基础实验的已签消息，不能遗漏 |
| 猜错目标且后续腐化 | 显式中止；该分支不能用于宣称无损模拟 |
| 最终签名使用另一 r | 不把 r 强制钉在缓存值上；仍检查内外实验的新鲜性 |

预算示例仅用 `Q_C=1,Q_S=2,Q_1=3,Q_2=4,ell=8,b_id=b_msg=8` 检查整数/分数计算：K=3，编程项 17/256，碰撞项 21/128，合计 59/256。**这是人为选取的极小概率模型，不是推荐密码参数。** 示例还未计入基础 IBS 与高斯误差，不能据此定安全等级。

33 项研究工具测试通过，其中本轮 20 项、上一轮 13 项。完整旧密码套件未重跑：src、参数与生产行为未变。精确枚举和符号流程检查没有验证真实签名、SIS 困难性或上述条件归约的所有概率步骤。
