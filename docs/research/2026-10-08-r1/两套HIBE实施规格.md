# 两套 HIBE 的实施规格

日期：2026-10-08。本轮冻结研究实施的算法、对象和接口，不冻结安全等级或正式参数。方法遵循 `src/ibme/hibe/api.py`；匿名密文不带公开身份。原始 bit/KEM 解码、字节适配与协议失败分别记录。

2026-10-09 补充：[CHKP T2 算法来源与有限采样契约](../team-chkp/T2-算法来源与采样契约-2026-10-09.md)。其中锁定 AP09/GPV08 作者版本、定位 MG02 ToBasis 来源，明确 GenBasis 子算法门槛、逐层 GS/宽度、有限重试与误差预算；附独立条件检查器。此补充不是 T2 实现完成，也不放行正式后端。

## 1. 首选 CHKP 的具体版本

依据固定 36 页作者全文 §5.1–5.3、Theorem 5.2。选择 **ROM ROHIBE、固定最大深度 2、§5.2 的匿名填充**，不混入 §5.4 的可容许哈希标准模型构造。完整原文见 [缓存](../../../papers/2010_bonsai_trees_cash.pdf)。

| 冻结入口 | 对应算法与对象 |
|---|---|
| setup | §5.3 GenBasis 输出 $A_0\in\mathbb Z_q^{n\times m}$、完整整数基 $S_0$；公钥含最大深度与参数上下文 |
| extract(rcv) | $A_1=[A_0\mid H(rcv)]$；ExtBasis、SampleD 和 RandBasis，保存接收者身份与可委派基 |
| derive(sk1,phi) | $A_2=[A_1\mid H(rcv,phi)]$；同样扩展/随机化，身份顺序固定；解封装原像由 $G(rcv,phi)$ 确定目标 |
| encrypt | 原文 KEM/dual-Regev bit 算法；字节适配对应 §5.1/5.2 的多比特描述，另保留独立逐比特对照 |
| decrypt | 用叶节点整数原像解码；字节解析失败返回 None；匹配拒绝在规范载荷和协议验签一起验收 |
| load_ciphertext | 只解析公开字段，不调用密钥提取、不反序列化 pickle；拒绝未知版本、尺寸越界和非规范系数 |

根、父、子矩阵列数分别是 $m,2m,3m$；完整基分别是这些列数的方阵。短整数向量用于解封装，不能替代父节点的完整格基。叶节点可按原文省略委派基；若采用按位懒生成原像的研究适配，须保留支持该生成的私有基，并单独记录尺寸。

**重复身份的状态要求是原文的一部分。** PDF 第 22 页明确要求对同一身份重复返回相同解封装向量，可使用状态或可重复随机性。本项目研究版采用唯一发钥树和私有缓存：根只公开发一级密钥；二级从已签发的同一个一级对象派生。缓存键包括完整公钥上下文、身份路径及多比特位置，保存/加载恢复缓存。不能为了省事对同一地址重抽原像，也不能把公钥派生缓存当成私钥缓存。

## 2. CHKP 参数与载荷

参数对象须独立记录 $n,m,q,d=2,s_0,s_1,s_2,\widetilde L_0,\widetilde L_1,\widetilde L_2,\alpha$、随机/采样实现、容量及失败预算。

- 引用 Lemma 5.1、Equations (5.1)/(5.2) 的采样、噪声和模数条件；$\omega$ 和大 O 不能直接替换成 1。
- 每一级核验 $A_tS_t=0\bmod q$、整数秩及行列式 $q^n$；ExtBasis 后再 RandBasis，不公开父基子矩阵作为子密钥。
- 父/子基样本与解封装原像分布按引用算法实现，库的 Gaussian 宽度约定必须对应原文；不用均匀数代替。
- 从扩展父基生成本级原像与从随机化后的本级基再生成原像，输入 GS 界不同。后者（包括懒生成）须另记解封装宽度并重算噪声，不能自动沿用前者的 $s_t$；见补充契约 §6 和 CHKP PDF 22。
- §5.1 的多比特摊销共享加密前导，但每位使用独立 syndrome/原像。密文系数计数为 $3m+L$，独立 bit 对照为 $L(3m+1)$；材料化叶原像仍需约 $3mL$ 个整数，不能只报密文变小。
- 无身份的填充长度统一为最大深度的 $(d+1)m$；对外 frame 只含版本、算法、参数标识、长度和模系数。字节适配、随机预言机及多比特前提列入对应表，不宣称新原创。
- Theorem 5.2 的查询损失保留 $dQ_H^{d-1}Q_G$，此处为 $2Q_HQ_G$；不是 QROM 定理，不能由 IBS 的 QROM 标签升级整个组合。

原始 KEM 解码不自动检测全部错配或密文字节篡改。第一阶段独立数学 bit 测试可只核对解码方程；实现字节后端前，需冻结规范载荷/解析与协议认证的接口适配。任何新增受保护身份标签先提交明确编码说明，不悄悄改变密文格式。

## 3. ABB10 保留的对照版本

仅选择 CRYPTO 2010 §4。算法与参数沿用 [既有规范](../2026-10-04/ABB10两层HIBE算法与参数规范.md)：$F_2=AH_1^{-1}H_2^{-1}$、完整基补全和 RandBasis，均不是当前拼接教学代码的改名。

根、父、子维度保持 $m$。对象含完整整数基、两层身份和公开上下文；SampleR 为整体条件于模可逆的高斯矩阵，不能改为逐列筛选。BasisDel 的基补全、身份矩阵及逐层宽度分别对应 Definition 7、Theorem 3/4、§4.2；安全结论引用 Theorem 5 的经典 ROM 版本。

与 CHKP 分别实现，不共用一个含糊的 `derive` 数学过程。ABB 有既有规范，但公开 SampleR、大矩阵变换和固定维度补全的工程工作更多，因此本轮把 CHKP 放在首套研究实施的位置；这不是已经测出的性能优胜结论。
