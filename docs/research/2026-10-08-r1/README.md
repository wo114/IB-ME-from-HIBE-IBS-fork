## 1. 本轮工程选择

**首套研究实施：CHKP §5.3 的两层匿名 ROM HIBE + Luo 等 2024 §3 的矩阵 IBS。** HIBE 交队友，IBS 由主 AI 下一轮实施。它保留 Wang 组合和 `(rcv,phi)` 顺序；两个原语都具有直接方案论文。选的是先形成真实研究实例的工程路线，不是经过同等级性能比较的最优排序或生产安全选型。

理由：CHKP 全文提供完整委派、状态说明及多比特摊销入口；Luo 的基本矩阵算法不需要 IBS 陷门采样，也不依赖尚未明确的 Hint 压缩模数。先实现基本算法，再扩展模格，不为抢先填写三个安全实例而跳过条件。

ABB10 保留固定维度 HIBE 对照。Luo 模格压缩版等待精确/兼容模数与格式核对；SRGG 的底层强结论、模数条件和尺寸表未形成完整对应，暂列储备；Yu 2026 等全文后再实施。原有三组仍是研究目标，最终按真实后端和假设记录，不计配置或参数数量。

**首套状态：仅研究实施规格已冻结。** 新的正式参数、安全声明和完整密文认证仍为 WIP；旧生产教学后端不变，`security_claim: none`。

## 3. 参数核验得到的具体结论

1. CHKP 两层子矩阵是 $n\times3m$，不能照搬固定维度 HIBE 的对象大小；原文还要求同地址固定解封装向量。
2. Luo Table 1 若按 bit 长度、Hint 的整除与 NTT 条件读取，三组共得到十个整数模数候选；Sage 确认只有第一组的 $14952038401$ 为素数，其余为合数。该模数不是已取得的作者精确参数，不能据此继承原安全估计。
3. Luo 的所有这些候选超过旧 `Params` 的 uint32 限制；禁止截断。后续研究配置独立保存，旧类型/格式保持兼容。
4. SRGG 非单位公开矩阵的容量核算对应 Table 4；Table 1 仍有差异。按两种字面模数映射读取 Theorem 1 的 $q>2\gamma$，三组均不满足；尚缺两节之间的明确映射，不能把它当作已成立前提，也不宣称已经攻击论文。
5. CHKP 原文的多比特摊销可显著减少前导重复，但会保留多 syndrome、原像和缓存成本。例子只作系数计数，不是实际速度、内存或安全参数结果，更不是本项目原创密码构造。

只运行公开算术，不生成新的 HIBE/IBS 密钥、签名或密文。计数例子使用 $m=128$、17 bit 模数长度、32 B 消息和作者报告的三档签名容量，不包含实际 framing；身份长度不适用。环境为指定 WSL Sage 及 Windows Python，见核验记录。算术检查不能替代安全证明或真实估计。
