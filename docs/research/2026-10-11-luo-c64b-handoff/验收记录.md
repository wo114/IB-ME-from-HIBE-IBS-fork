## 版本与失败记录

1. 独立子智能体先在886fc12↔8b9500c验证；主Codex随后发现新目录已提交0bf0855。旧HEAD固定值被拒，`cross-version.json`保留退出2，不能写成算法失败；更新为已核对的完整新提交后，`cross-version-current.json`通过。
2. 两个目录所选23份密码核心源码完全相同。跨提交成功证明交接兼容，不代表测试了不同密码构造。真正的新assembly由另外的smoke验收。
3. assembly首次冻结了整个src，但对方按约定正在合并CLI，故保守拒绝；`assembly-current.json`及`assembly-diagnostic.json`保留。修正测试范围为非CLI已提交源码，实际加载路径/字节逐项核对，禁止把CLI或未列入提交的代码混入；`assembly-final.json`为通过记录。不为通过测试修改对方实现。
4. 新测试初次收集误从core.types导入BOTTOM，修正为公开的protocol.baseline入口；属于测试代码错误，不是密码算法错误。最终122项运行采用修正后的测试。
5. DeepSeek临时包未持久化；只接收已提取的stdout最终回执，并另写纠错说明。没有把不存在的13文件包标为本地哈希验证通过。

## 新共享框架调用示例

```python
from ibme.assembly import make_suite, validate_suite, build_runtime
from ibme.ibs.luo_module import LuoModuleParams

# values 为profile.json的完整params；已有helper的版本可用c64b_params()。
config = make_suite(hibe="abb10", ibs="luo-module", transport="hybrid",
                    protocol="byteauth-v1", signature_format="compact",
                    ibs_params=LuoModuleParams(**values))
report = validate_suite(config)
if not report.ok:
    raise ValueError(report.errors)
runtime = build_runtime(config)
public, master = runtime.proto.setup(runtime.hibe_params, ibs_params=runtime.ibs_params)
```

SuiteConfig保存完整参数和格式，不必先改全局默认或增加同名算法。CLI的合并、发布和持久化仍由共享框架所有者负责；本轮没有测试其尚在合并的CLI，也不将framework代码重复搬进Luo分支。
