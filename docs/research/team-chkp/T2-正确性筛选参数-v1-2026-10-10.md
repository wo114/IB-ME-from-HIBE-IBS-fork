# CHKP 正确性筛选参数 v1

日期：2026-10-10。该组参数用于替代原 `n=1,q=2` 教学参数，检查 CHKP 深度二 HIBE 的公开正确性关系。它不是正式安全参数，也没有注册为生产后端。

## 1. 候选参数

| 参数 | 值 | 说明 |
|---|---:|---|
| `n` | 2 | 提高到非退化的最小筛选维度；不代表安全等级 |
| `m` | 64 | 根矩阵列数；使当前 GPV 叶维度 `3m=192` 触及研究上限 |
| `q` | 65537 | 素数，`ceil(log2 q)=17` |
| `m_0,m_1,m_2` | 64, 128, 192 | CHKP 深度二的根、一级、二级维度 |
| `s_1` | 16 (`s_1^2=256`) | 论文关系筛选宽度 |
| `s_2` | 64 (`s_2^2=4096`) | 论文关系筛选宽度 |
| `alpha` | `2^-16` | 工程筛选占位值；尚未完成原文 `omega` 条件证明 |
| `C` | 采用 `3/2` 作为筛选记录 | 原论文只要求固定常数 `C>1`，没有指定本项目的正式值 |

这组参数的 `m/(n ceil(log2 q))=64/34=32/17≈1.882`，因此满足本轮明确记录的 `C=3/2` 筛选假设。这个 `C` 是本项目的候选筛选假设，不应写成 CHKP 原文指定的常数。

## 2. 已通过的静态正确性关系

论文 Lemma 5.1 和式 (5.1)/(5.2) 要求的已知模数—宽度关系在两级均通过：

\[
65537 \ge 4\cdot16\cdot(128+1)=8256,
\]

\[
65537 \ge 4\cdot64\cdot(192+1)=49408.
\]

现有预筛器实际输出 `known_static_conditions_passed=true`，机器证据见 [T2-paper-preflight-correctness-v1-2026-10-10.json](T2-paper-preflight-correctness-v1-2026-10-10.json)。

这只说明已知的维度、素数、模数—宽度关系通过。`alpha` 的 `omega(sqrt(log n))` 尾部因子、真实 GS 界、采样失败预算和解密噪声仍未闭合。

## 3. 当前 GenBasis 的实际阻塞

该候选不能直接接入当前有限 AP09 生成器，原因已经通过 Sage 环境复核：

- `n=2,q=65537` 时，当前 AP09 代码使用 `ceil(log2 q)=17`，要求 `random_rows > 34`；
- 取最小可行 `random_rows=m1=35` 时，`m2` 至少为 138，根维度至少为 `m1+m2=173`；
- 为通过当前有限 AP09 质量门，示例至少需要 `hadamard_scale=18`；
- 对应一级、二级维度为 346、519，均超过当前 GPV 研究上限 192。

因此当前结果是：

| 环节 | 结果 |
|---|---|
| CHKP 公开静态参数关系 | 通过 |
| 当前 GPV 维度筛选 | `m=64` 候选本身通过 |
| 当前 AP09 根基生成 | 根维度最低约 173，与候选 `m=64` 不兼容 |
| 两级真实采样 | 尚未运行，因 GenBasis 入口不兼容 |
| 安全声明 | `security_claim: none` |

这不是采样器已经发现的数学错误，而是当前有限 AP09 实现的维度构造和 GPV 资源上限共同形成的实现边界。

## 4. 与原小参数的关系

原 `n=1,m=10,q=2` 参数继续保留，用于路径、LLL 对照、叶原像和缓存回归。它不满足 `q >= 4s_t(m_t+1)`，所以不能承担 HIBE 解密正确性实验。

本 v1 候选承担论文关系筛选，但由于当前 GenBasis 边界尚未接通，也不能宣称完整正确性。两组参数的职责不能混用。

## 5. 后续决策顺序

1. 先不修改 `SampleD`；当前阻塞首先位于 GenBasis/维度接口。
2. 评估采用论文另一种 GenBasis 构造或放宽研究实现的维度上限，重新生成 `m=64` 的根基。
3. 重新测量真实 `ExtBasis`/`RandBasis` 的 GS 界，不能继续把 `s_1=16,s_2=64` 当作已证明宽度。
4. 通过真实基和噪声条件后，再决定这组候选是否升级为正式参数候选。

本文件及机器证据不作 NIST 安全等级、ROM 安全或完整 HIBE 正确性声明。
