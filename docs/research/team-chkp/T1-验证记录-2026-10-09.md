## 1. 环境与声明

- Windows 主机处理器：Intel Core Ultra 7 255HX，20 核、20 逻辑处理器。
- 执行环境：WSL Ubuntu-24.04、Linux x86_64，激活 `~/miniconda3/envs/sage`。
- Python 3.13.15、Sage 10.9、pytest 9.1.1；本轮未安装依赖。
- 所有 CHKP 参数均为公开代数样例，`security_claim: none`，`is_randomized: false`。
- 本轮无实际身份、消息或密文；不涉及 ROM 查询实验，不产生秘密密钥，不测量安全位数。
- 以下耗时为测试框架打印的墙钟时间，不是公平算法性能基准。未做 CPU 固频、性能隔离或硬件加速对比。

## 2. 执行顺序与实际结果

每次命令均在仓库根目录、激活上述 Sage 环境后执行。以下精简掉 WSL 的 localhost 代理提示；该提示没有改变测试退出码。

### 2.1 复现原交接失败

```bash
PYTHONPATH=src python -B -m pytest -p no:cacheprovider tests/test_chkp_basis.py
```

结果：`2 failed, 14 passed in 3.80s`，退出码 1。

失败位置分别是原测试第 32 行 `a_z * s_z`、第 59 行 `a * v` 的逐行迭代，异常为将 Sage `Vector_integer_dense` 转为 `int` 的 `TypeError`。

将这两处及后续 `coords` 改为 `.list()` 后，原命令精简输出为 `16 passed in 3.77s`。没有删掉断言、标记 XFAIL 或跳过。

### 2.2 子智能体边界测试与数学审查

边界测试提交：`6f55f7dd708033646ff6fec10588e5f710b19643`，`test(chkp): cover T1 boundaries`。其独立运行报告为 `119 passed in 4.67s`，由主智能体随后合并回归复核。

另一子智能体只读审查完整格/ExtBasis/GS，发现原非前导主元与幺模变换样例不充分。主智能体增加显式主元位置和真实改变 GS 的样例后再验收。置换公式反例同时经独立标准库整数计算核对。

### 2.3 输入契约先失败、后修复

新增的 5 项源环契约测试，在修改实现前结果为 `4 failed, 1 passed, 9 deselected in 3.73s`。

- 两项异模数输入及一项整数基输入确实被旧实现默默接受。
- 扩域输入旧实现已经拒绝，但只在整数转换阶段报错，新增测试要求统一的源环检查，因此该项是错误信息/校验阶段不匹配，不应误报成旧实现接受了扩域。
- 同域和调用者显式选择整数提升的正向用例通过。

修复后，T1 的三份测试统一运行：

```bash
PYTHONPATH=src python -B -m pytest -p no:cacheprovider -q \
  tests/test_chkp_basis.py tests/test_chkp_basis_boundaries.py tests/test_chkp_t1_audit.py
```

结果：**`152 passed in 5.33s`，退出码 0，无失败、跳过或预期失败。**

计数拆分：原测试及新增主元用例 19 项；边界契约 119 项；独立审计/负向对照/源环修复 14 项。
