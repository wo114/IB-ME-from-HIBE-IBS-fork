# Luo 模格版：返工后的测试与性能证据

这次交付的重点是：**把前几轮报告中的说法改成可以实际检查的测试和数据。** 没有改 Luo 算法、参数、默认签名格式，也没有修改 CHKP。测试对象仍是现有的 **ABB10 教学 HIBE + Hybrid + Luo 模格 IBS + BYTEAUTH**。

基线为上游 `bc22c9cb834dee51e9c8b7a37040fa0c5349fcdb`。本目录与测试代码在独立工作目录整理，没有混入主目录里其他人的未提交文件。

## 1. 这次具体补了什么

| 内容 | 原来的不足 | 现在交付的东西 |
|---|---|---|
| 攻击测试 | 看见解密失败，就猜是某一层拒绝 | 在关键调用处加观察点，检查是否走到了 HIBE、载荷解析、IBS 验签 |
| 换系统、换格式 | 两者容易混在一起解释 | 同公钥换格式单独测试；CLI 四个状态均独立初始化，单独记为跨系统拒绝 |
| CLI 可移植性 | 可能误用本机已安装代码，中文路径受编码影响 | 从测试位置确定仓库路径，断言子进程实际加载该源码，显式严格 UTF-8 |
| 性能 | 旧“Setup”只测了创建对象；codec 只测了解码 | 新测实际 Setup，以及同一个数学签名的编码、解码、验签；保留原始 CSV |
| 签名拒绝账本 | 正常调用、负控与理论概率容易混淆 | 逐调用、逐尝试重新核账，正常 108 次与人为负控 3 次分开 |
| HIBE 接口容量 | 容易把整个签名算成底层逐比特加密量 | 两格式公共调用探针检查：外层装签名与消息，底层收到 32 B 种子、86 B×2 编码身份 |

新增候选回归为 49 项：第十七步原 37 项的修订版，加 12 项分层测试。连同11项账本/计时器回归及既有相关测试，本轮单次运行 **317 passed，退出码0，25分39秒，无失败或跳过**。这是选定范围回归，不是全仓库全部测试。完整命令和JUnit见 [验收收据](验收收据.md)。

测试代码在 [tests/luo_acceptance](../../../tests/luo_acceptance/)。这里“验收”指选定范围的实现检查，不代表后端安全准入。

## 2. 哪一层负责拒绝，已经分清楚了

| 场景 | 本轮测试观察的边界 |
|---|---|
| A 系统密文交给 B 系统 | BYTEAUTH 的公钥上下文先拒绝，未调用 HIBE Derive；原 OTS 本身仍有效 |
| 把旧载荷重新加密到 B 系统 | B 系统 HIBE 确实恢复原载荷，随后 IBS 加载器拒绝旧公钥上下文 |
| 截断、追加、重复、改载荷域 | 修改后的明文能由 HIBE 恢复；载荷解析器被调用，IBS 签名加载尚未发生 |
| 换一把有效 OTS，但保留原签名和 envelope | IBS 验签先返回 True，随后 BYTEAUTH 发现 OTS 承诺不一致而拒绝 |
| 同公钥，只换 reference/compact 解码器 | 两边各有正常解密对照，错误格式到达 IBS 签名加载器并被拒绝 |
| 裸 CPA 胶囊低位修改 | 保留“底层仍恢复同一个种子”的负面对照；Hybrid 对完整 capsule 的 AAD 认证拒绝修改 |

原样重放同一个合法密文仍能解密；本项目没有把“所有重放都拒绝”作为现有功能。CLI 的状态不变检查仅比较 `msk.bin`，不扩写为整个缓存目录没有变化。普通端到端拒绝用例若没有观察点，只报告整体拒绝。

## 3. 性能现在可以说到什么程度

新补测的 [raw.csv](evidence/setup-codec/raw.csv) 共 50 行，5 个新系统、每个系统 1 个真实数学签名；两格式对同一签名分别编码、解码、验签。每一项有 5 次观测，交替格式先后顺序。完整参数、环境、源代码哈希、计时范围见 [metadata.json](evidence/setup-codec/metadata.json)，汇总见 [summary.json](evidence/setup-codec/summary.json)。

| 项目 | 本次中位数 | 计时范围 |
|---|---:|---|
| 真正 Setup | 0.2881 秒 | 协议内部的 HIBE 和 IBS 初始化，不含运行对象创建和公钥编码 |
| 首次签名密钥提取 | 0.6284 秒 | 每个新系统第一次给 Alice 发钥 |
| 已发钥缓存命中 | 0.0095 毫秒 | 同一系统再次取 Alice 的固定密钥；不是重新发钥 |
| IBS Sign | 0.5844 秒 | 256 B 原语消息，包括算法内自验，不含线格式编码 |
| reference / compact 编码 | 0.9564 / 3.3880 毫秒 | `to_bytes` |
| reference / compact 解码 | 3.2666 / 3.2192 毫秒 | `load_signature`，含解析校验，不含验签 |

这些是本机小样本描述数据，不能推出紧凑版整体更快、一般性的算法性能排名或安全等级。签名对象格式有差异，数学签名相同；编码成本与传输尺寸的取舍要分别看。

旧第十七步 30 次完整加解密 CSV 作为历史证据保留，按 0/256/3924 B 消息分别统计、每格式每档 5 次。它采用同一系统密钥，但两格式随机流不同，15 组中 14 组签名尝试数不同，不能称作“完整链路同随机带对照”。完整 Encrypt 包含签名编码，完整 Decrypt 包含内层解析，旧“codec 不在总计时里”的说法不采用。

实测签名为 **29,455 B / 16,063 B**。在 3924 B 应用消息下，外层 HIBE 载荷为 **33,487 B / 20,095 B**；历史完整教学密文为 **2,584,180 B / 2,570,788 B**，均减少 13,392 B，后者约 **0.5182%**。签名变小不能直接等同完整密文同比例变小，更不能当成 CHKP 尺寸结果。

## 4. 哪些结论仍然不能写

- 历史账本：108 次正常调用、1000 次尝试，`ez=459 / elow=796 / ew0c=0 / ez∩elow=363`；正常中止为 0。3 次人为负控是另一本账，不是 3 次正常中止。观察器读取密钥内部字段，只是白盒诊断；其输出不包含私钥或随机带。测试中没有失败不能给出理论中止概率。
- 前几轮的 **0.11837、2^-186.1** 不作为真实成功率或中止界。真实 LowBits 联合概率、Sign 总中止界仍未知。独立模型的计算不能冒充实际固定公钥、相关挑战下的证明。
- 安全理论仍按原论文和 Wang 组合条件作引用映射，不重做 Luo 完整归约，不增加 QROM 声明。
- 本轮没有接入或验收 CHKP。32 B 种子合同、两格式载荷和 86 B 身份是当前 ABB10 教学接线结果；未来 CHKP 的逐位设计、资源、参数与固定叶密钥语义须由其专属任务独立交付。旧交接中的资源帽不在这里重新宣布为最新实现能力。

始终保持 `security_claim: none`、`backend_admitted: false`、`parameters_are_formal: false`。性能与功能通过不替代正确性证明、参数安全估计或正式安全归约。

复算旧数据：在仓库根执行 `python -B experiments/research/audit_luo_acceptance_evidence.py`。重测新分项前设置 `PYTHONPATH=src`，然后执行 `python -B experiments/research/luo_acceptance_benchmark.py --output outputs/luo-setup-codec-new --repeats 5`。运行需要项目测试环境和 Hybrid 的 cryptography 依赖；本轮没有另行安装或改变环境。
