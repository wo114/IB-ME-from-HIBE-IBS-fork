# Luo 第二十二步：补出中止概率界，找到可运行的新参数

2026-10-11。本轮接着处理上次留下的四项：LowBits相关性、总签名中止界、参数选择、真实CHKP组合。**前两项得到有明确假设的数学界；新参数已实跑和独立估计，但没有升级正式安全声明；真实CHKP组合仍缺后端。** 不把四项全部写成完成。

## 1. 这次到底解决了什么

以前只能说“这些测试签名成功了”，不能回答正常使用时“反复尝试还一直失败的概率有多大”。问题在于LowBits各坐标、挑战与掩码有相关性，不能直接把各项通过率相乘。

这次换了证明对象：找出一块**无论合法挑战如何选择都能通过的随机掩码区域**，证明绝大多数诚实生成的公开矩阵上，这块区域有统一的最小概率。再把重试上限、发钥失败、随机整数拒绝、哈希解码及外部查询预算一起加进去。

这不要求整个LowBits向量联合均匀，也不恢复此前撤回的0.11837和2^-186.1。精确联合分布仍未求出，但为给中止上界已经不必求它。

- [完整条件式推导](鲁棒接受集与中止界.md)：圆周LowBits、环零因子、好矩阵、适应性历史、有限随机与XOF耦合。
- [独立复核和返工](独立复核与返工.md)：DeepSeek指出两处必须写清的条件，Codex补齐；审查意见也经过再核验。
- [参数筛查](参数选择与安全边界.md)：不能只为减少拒绝而忽略攻击成本和挑战空间。

## 2. 给出一套实际跑过的研究候选

候选名 **availability-k64 / C64B**。仍是Luo原文§4的模格路线，保留κ=64，不切换矩阵算法。它不是论文参数表的逐字复制，不替换仓库默认值。

| 参数 | 当前默认 | C64B研究候选 |
|---|---:|---:|
| N、k、ℓ、q、η | 256、11、10、274877844481、1 | 相同 |
| κ | 64 | 64 |
| γ1 | 125440 | 190000 |
| γ2 | 31470387200 | 60000000000 |
| γ3 | 15270991360 | 27487784448=(q−1)/10 |
| d | 28 | 28 |
| 发钥／签名重试上限 | 各1024 | 各4096 |

均匀整数抽样帽仍128；缓存64身份；身份64 B、IBS消息4096 B；root=153250464611。完整17字段由[数值证书](evidence/k64-certificate.json)保存。提高重试帽不等于每次都跑4096遍，成功后仍立即返回；但最坏资源上限确实增加。

在独立理想随机源／理想XOF模型下，一次Setup、最多64个新身份、65536次签名、额外至多2^64个新挑战预言机查询，其**正常调用总中止概率上界小于2^-153**，数值证书log2约−153.8569。包含一次坏矩阵事件；不是对任意恶意选择矩阵的保证。

单独看好矩阵上的签名重试帽约2^-173.897、发钥帽约2^-159.947；有限来源和哈希项另计。完整分子／二进制分母见[生命周期证书](evidence/k64-lifetime-certificate.json)，浮点log2仅便于阅读。这个153不是密码学安全位数，也不代表程序已经实际跑了65536次签名。

## 3. 实际做了哪些实验

每候选均为3个独立测试系统×身份长度1/5/64 B×消息长度0/256/4096 B×2次，共54次Sign。第二次使用从主状态恢复后取出的密钥；缓存取钥和验证用禁止取熵的检查源。每份签名分别编码、加载、验证reference和compact。

| 本轮配置 | Sign调用／内部尝试 | reference签名 | compact签名 | 结果 |
|---|---:|---:|---:|---|
| C49：κ49、γ1=145000、γ2=34000000000，其余见证书 | 54／293 | 29455 B | 16062 B | 全部通过 |
| C64B：保留κ64的新候选 | 54／315 | 29455 B | 16383 B | 全部通过 |

每行另有30条Setup／发钥／缓存／恢复阶段记录，以及108次双格式编码后验签。只记录尺寸、计数、时间和公开测试标签，不保存密钥、签名字节或随机带。两候选不是同随机带配对性能实验，不能由293比315少就宣称C49更快。

最终选定10个测试文件：**269 passed，23.25秒，退出码0，无失败／错误／跳过**。覆盖原212项Luo生命周期／算法测试与本轮57项数学、小域穷举、异常分母、来源哈希及证据篡改检查；不是全仓库或Sage/CHKP验收。[JUnit](evidence/final-regression.xml)。

证据审计首次把C49的compact尺寸误沿用默认16063 B，实际是16062 B；断言抓到后修正预期值，原始数据没改，保留[失败JUnit](evidence/evidence-tests.xml)。这不是通过删断言使测试成功。

## 4. 为什么仍不能写“正式安全参数已全部完成”

C64B已经是**明确、能运行、有条件式可用性界、有独立攻击模型估计**的候选，不再只有小参数或口头设想。建议用它继续论文条件和组合验收。

但模型估计不是完整安全等级：其MSIS系数模型经典／量子成本指数为188.340／170.925，比默认降低8.468／7.685；挑战空间不下降，但不能据此给整个IBS授予128位或NIST等级。还必须保留引用覆盖、固定密钥缓存与模拟、归约损失及真实SHAKE实例化的边界。按既定分工，不重做Luo完整基础安全归约，也不升级QROM。

因此仍为 security_claim=none、backend_admitted=false、parameters_are_formal=false。没有改src、默认参数、默认reference格式或旧密钥配置。参数进入公钥上下文，换候选必须重新Setup，不能混用旧密钥。

## 5. CHKP组合：卡在什么地方

主Codex复跑接入检查：26项检查器测试、18项公共边界探测通过；但真正预检退出码为2，原因是 **CHKP_PUBLIC_BACKEND_MISSING**。这是没有可交给Hybrid的真实CHKP后端，不是因none标识禁止功能实验。

现有first_suite有256个位置和种子封装函数，不等于完整HIBE对象；CHKP私有第七步原型的同叶帽32也不能用8个身份拼成256目标。真实32 B种子加解密仍须由CHKP负责对话交付。

本候选只影响外层签名尺寸：默认compact16063 B变为16383 B。按现有载荷公式，应用最大3924 B时外层compact载荷从20095变为20415 B；这是长度推导，不是CHKP实跑密文尺寸。内层有序身份仍(rcv,phi)，各86 B，种子仍32 B。接入影响已同步CHKP对话。

下一次真实组合验收要在包含双方提交的共同版本上进行：Setup→接收者发钥→发送者叶派生→32 B种子封装／解封→Hybrid→Luo验签→四种身份匹配及分层篡改测试。教学ABB10记录不能顶替它。

## 6. 复现与证据入口

仓库根设置PYTHONPATH=src、PYTHONDONTWRITEBYTECODE=1，然后：

~~~text
python -B experiments/research/luo_robust_abort_certificate.py --profile availability-k64 --extracts 64 --signs 65536 --oracle-queries 18446744073709551616
python -B experiments/research/luo_candidate_probe.py --profile availability-k64 --output outputs/luo-c64-new-run
python -B experiments/research/audit_luo_candidate_probe.py docs/research/2026-10-11-luo-abort-bound/evidence/candidate-k64-probe/probe.json
~~~

实验输出目录必须不存在；正式复跑应像本轮一样外包600秒进程超时。证书只算数学，不签名；probe才跑密码算法。测试随机流不用于生产秘密。

- C49原始probe对应的两个实验脚本旧快照保留在其source-snapshot；其余六项源文件与当前一致。C64B八项源文件与当前一致。
- evidence/parameter-screen 保存两个候选和默认值的估计器输入、输出、脚本与独立报告；原报告写作时的待审状态保留，当前结论以本README和返工说明为准。
- evidence/integration-check 是本机、固定f079ce1输入的旁路来源快照和主Codex复跑记录，不是新公共框架或可移植CHKP实现。脚本默认路径及旧HEAD须显式审查后适配，不能不改输入就当新提交回归。
