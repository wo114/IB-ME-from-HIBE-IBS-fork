## 1. 当前方案范围

项目继续采用王老师论文中的“两层匿名 ROM HIBE + IBS”通用构造，身份顺序固定为 `(parent_id, child_id) = (rcv, phi)`。本轮 CHKP 工作对应两层匿名 ROM HIBE 的实现研究，不加入 Boyen–Li 增强隐私，也不把经典 ROM 结论升级为 QROM。

R1 当前首套研究路线是 CHKP/Bonsai Trees HIBE + Luo 2024 IBS。两边仍分别验收：CHKP 负责 HIBE、格基和采样；主线 IBS 负责 IBS、协议和最终组合。具体 IBS 后端尚未因本轮 CHKP 结果自动切换，完整组合的参数和安全准入仍由队长统一确定。

## 3. 参数结果

### 3.1 原小参数：保留为回归基线

当前叶路径使用的公开教学参数为：

```text
n = 1, q = 2, m = 10
m0, m1, m2 = 10, 20, 30
s1^2 = 9064, s2^2 = 15952640
epsilon_bits = 16
```

它可以用于 T1、采样路径、LLL 对照和缓存回归，但不满足 CHKP KEM 正确性关系 `q >= 4s_t(m_t+1)`，因此不能用于宣称完整 HIBE 解密正确性或安全等级。原参数不删除，也不再作为正式候选继续扩展。

### 3.2 正确性筛选参数 v1

本轮新增候选：

```text
n = 2, m = 64, q = 65537
m0, m1, m2 = 64, 128, 192
s1 = 16, s2 = 64
alpha = 2^-16  # 当前工程筛选占位值，不是安全等级
```

它通过了已知静态关系：

```text
65537 >= 4 * 16 * (128 + 1) = 8256
65537 >= 4 * 64 * (192 + 1) = 49408
```

但当前有限 AP09 生成器对 `n=2,q=65537` 至少需要约 173 的根维度，因而一级、二级维度约为 346、519，超过当前 GPV 研究上限 192。这组参数已经完成“论文关系通过、实现边界定位”，尚未进入真实采样。

详细记录：[正确性筛选参数 v1](../../research/team-chkp/T2-正确性筛选参数-v1-2026-10-10.md)；机器证据：[预筛 JSON](../../research/team-chkp/T2-paper-preflight-correctness-v1-2026-10-10.json)。

## 4. 当前关键阻塞

1. **GenBasis 与两层维度不兼容。** 当前 AP09 有限构造和 GPV 维度上限组合过紧，不能只继续增大 `q` 解决。
2. **LLL 还不是最终方案。** 现有 LLL 是项目额外的确定性后处理，不是 CHKP 原文的 `RandBasis` 替代；若正式采用，必须补资源、失败概率和分布映射。
3. **真实参数条件未闭合。** `alpha` 的尾部因子、各级真实 GS 界、SampleD/RandBasis 随机带、有限中止和解密噪声尚未在同一组参数下闭合。
4. **完整 HIBE 尚未验收。** 真实 `H/G` 身份映射、bit/multi-bit Encaps/Decaps、字节适配、完整 contract tests 和端到端 IB-ME 尚未完成。
5. **安全与性能尚不能宣称。** 目前没有正式安全等级、完整 ROM 归约实例、生产密钥处理或公平的完整 IB-ME 性能对照；功能测试不替代安全证明。

1. 队长确认采用哪一种 GenBasis 路线，或是否允许扩大研究实现维度上限；

7. 最后再冻结正式参数、安全声明和比赛报告口径。
